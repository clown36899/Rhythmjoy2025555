# 자유게시판 새 댓글 읽음과 목록 배지

- 날짜: 2026-09-19
- 상태: 로컬 구현·자동 검사·별도 브라우저 화면 검증 완료. 배포/운영 스키마 변경 전.

## 맥락과 기존 소유자

하단 숫자는 이전까지 최근 14일 미읽음 게시글만 셌으며 댓글은 입력이 아니었다. 사용자는 관리자 로그인 중 이미 읽은 글의 숫자 1을 보고 댓글 변경도 알아볼 수 있도록 요청했다. 기존 `user_board_post_reads(user_id, post_id, read_at)`, `/api/board/free/unread`, `/api/board/free/read`, `useFreeBoardUnreadState`, `CommentSection`, `StandardPostList`를 유지한다.

기존 구현 판정은 일부 있음이다. 본문 읽음과 계정/탭 동기화는 있으나 댓글 단위 읽음은 없다. 단순 댓글 총수 차이는 삭제/재등록을 구분하지 못하고, 본문 상세의 `read_at`만 쓰면 댓글 조회 실패·느린 응답·본문 전용 미리보기에서도 보지 않은 댓글을 읽었다고 처리하게 된다.

## 결정

기존 사용자/글 읽음 행에 nullable `read_comment_ids LONGTEXT` 한 필드로 실제 렌더된 댓글 ID 배열을 저장한다. 새 테이블·큐·알림 원장·시간 UI는 없다. 서버와 게스트는 `src/utils/freeBoardActivity.mjs`의 동일한 분류를 사용한다.

- 최근 14일 공개 자유글의 미읽음 본문은 기존 제목 `NEW`로 표시한다.
- 최근 14일 공개 댓글의 미읽음 수는 글 나이에 관계없이 댓글 수 옆 `+N`으로 표시한다. 본인 글에 타인이 쓴 댓글은 포함하고 본인이 쓴 댓글·숨김 댓글·숨김/삭제된 부모 글·지난 댓글은 제외한다.
- 하단/홈 숫자는 미읽음 본문 수 + 미읽음 댓글 수이며 접근성 문구도 새 글·댓글로 구분한다. 푸시나 알림함을 생성하지 않는다.
- 본문 조회는 본문만 읽음 처리한다. `CommentSection`의 성공한 현재 게시물 조회가 렌더된 뒤, 탭이 보이는 경우에만 그 스냅샷의 ID를 전달한다. 늦게 도착한 이전 글의 응답, 실패한 조회, 숨김 댓글은 읽음으로 전달하지 않는다.
- 서버는 현재 게시물에 실제 속하는 공개 최근 댓글 ID만 인정한다. 동일한 읽음 행을 트랜잭션 잠금으로 직렬화하고 기존 ID 집합과 합친다. 늦은 탭 요청이 다른 탭의 읽음을 지우지 않으며, 스냅샷 후 도착한 댓글도 읽음으로 추가하지 않는다. 삭제된 과거 읽음 ID는 집합에 남아도 새 활동 계산에 영향을 주지 않는다.
- 레거시 행의 필드가 NULL이면 기존 `read_at` 이전 댓글을 기준으로 삼는다. DB `UNIX_TIMESTAMP(read_at)`를 사용해 드라이버 시간대 변환을 배제한다. 첫 저장 시 이전 기준을 스냅샷으로 고정한 후 본문 `read_at`을 갱신한다. 기존 클라이언트의 본문 전용 호출도 새 댓글을 일괄 지우지 않는다.
- 게스트는 기존 본문 ID 키를 유지하고 댓글 ID 키만 같은 훅이 소유한다(최근 저장 ID 최대 10,000개). 기존 게스트 기록에는 댓글 확인 시각이 없어 과거 댓글 읽음을 추측하지 않는다. 회원 기록과 합치지 않는다.
- Cafe24의 기존 구독은 no-op이므로 화면/네트워크 복귀 시 기존 목록·댓글 조회를 다시 연결했다. 이는 실시간 서버 전송 도입을 의미하지 않는다. 목록의 늦은 응답도 배지와 같이 최신 요청을 덮어쓰지 못하도록 한다.

## 배포와 롤백

기존 deploy 명령에 멱등 SQL 마이그레이션과 공통 모듈 전송을 추가했다. 운영 적용 시 기존 읽음 테이블 생성 다음 새 필드를 추가하고 서버를 재시작해야 한다. 기존 PK·행·`read_at`은 보존한다. 구 버전으로 롤백할 때 컬럼을 삭제할 필요가 없으며 이전 코드는 추가 필드를 무시한다. 이번 작업 중 운영 DDL·데이터 쓰기·배포는 수행하지 않았다.

## 검증과 남은 일
