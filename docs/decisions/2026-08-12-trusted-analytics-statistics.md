# 방문자·스윙씬 통계의 권위 원본과 신뢰성 계약

- 날짜: 2026-08-12
- 상태: 채택

## 배경

운영 통계 화면의 날짜 범위는 KST로 보였지만 범용 API가 ISO 시각을 문자열로 비교해 UTC 저장값과 다른 하루를 읽을 수 있었다. Android 인앱 브라우저에서 Chrome으로 넘기는 동안 두 저장소가 각각 방문 세션을 만들었고, referrer·UTM은 마지막 요청 값으로 바뀌며 sequence는 새로고침 때 초기화됐다. 이 때문에 고유 방문자보다 원시 세션과 활동 건수가 더 쉽게 부풀고 유입 출처를 사후에 입증하기 어려웠다.

스윙씬 통계는 운영 이벤트를 읽으면서도 개최 회차·등록 건수·장르 분류·도달 효과의 정의가 분리되지 않았다. `socials`에 이미 포함된 club을 다시 더하고, 실제 조회 표본이 없는 홍보 도달율을 표시하며, 제목과 별도 재조회로 상세 항목을 추정하는 경로가 있었다.

## 결정

1. 방문자 일자 경계는 `Asia/Seoul`의 절대 시각으로 전달하고, 양쪽이 timezone을 가진 ISO 시각일 때만 epoch로 비교한다. 날짜 전용 필드는 달력 문자열 비교를 유지한다.
2. 고유 방문자와 핵심 세션 품질은 클라이언트가 아니라 동일한 서버 순수성 필터 결과에서 계산한다. 30분 이내 같은 방문자의 원시 세션을 논리 세션으로 병합하고 활성 체류는 세션당 30분을 상한으로 둔다.
3. Android 인앱→Chrome 인계 문서는 분석 대상이 아니다. 인계 URL에는 기존 캠페인 값을 보존하면서 출처가 없을 때만 인앱 소스와 `in_app_handoff`를 붙인다.
4. 세션 sequence와 최초 referrer·UTM·landing은 해당 탭의 세션 저장소에 보존한다. 이후 페이지 이동이나 새로고침이 최초 유입 정보를 덮지 않는다.
5. 스윙씬 통계의 권위 원본은 운영 `events`의 구조화 필드다. 지원 분류와 공개 상태를 통과한 행만 포함하고, 비어 있지 않은 `event_dates`를 개최 회차 원본으로 사용한다. 없을 때만 시작일 한 회로 대체하며 날짜 범위를 임의로 확장하지 않는다.
6. 기본 기간은 기준일이 속한 달을 포함한 최근 12개 달력월이다. 과거 회차와 현재 월의 등록된 예정 회차를 포함하되 화면에 이 정책을 명시한다. 개최 회차 수와 고유 이벤트 수는 별도 지표로 제공한다.
7. 중복은 제목·개최일·시각·장소·유형이 모두 같은 회차만 제거하고 더 완전한 메타데이터 행을 남긴다. 제거 건수를 화면과 응답에 공개한다.
8. 장르는 구조화된 `dance_genre`와 인정된 레거시 장르 토큰만 사용한다. 제목에서 추측하지 않으며 미분류는 숨기지 않고 분류 가능 회차/전체 회차를 품질 지표로 제공한다.
9. 조회 로그가 없는 효과 지표는 만들지 않는다. 홍보 효과 대신 등록일에서 첫 개최일까지 실제로 계산 가능한 리드타임 분포, 표본 수, 중앙값과 제외 표본을 제공한다.
10. 월별·요일별·장르별 그래프와 최대 개최일 상세는 한 번 생성한 서버 결과를 함께 사용한다. 응답은 집계 버전, 원본, 기준일·시간대·기간, 포함·제외·대체·중복·분류 품질을 포함하며 캐시는 버전별로 분리한다.

## 결과

동일 기간과 동일 운영 원본으로 핵심 숫자를 재현할 수 있고, 화면에서 숫자의 포함 범위와 한계를 확인할 수 있다. 실제 급증과 클라이언트 중복 수집을 분리하며 이후 인앱 공유 유입은 최초 출처를 더 정확히 남긴다. 스윙씬 화면은 “등록 이벤트 수”, “개최 회차”, “예정 회차”, “장르를 분류할 수 있는 표본”을 혼합하지 않는다.

현재 데이터에서 장르 분류율이 낮으면 그 한계를 그대로 보여준다. 이는 제목 추정으로 숫자를 채우는 것보다 보수적이지만, 향후 등록 폼과 수집기의 구조화 장르 품질을 개선할 명확한 기준이 된다. 이 결정은 기존 데이터를 소급 수정하지 않으며 배포 전 운영 DB에는 쓰지 않는다.
