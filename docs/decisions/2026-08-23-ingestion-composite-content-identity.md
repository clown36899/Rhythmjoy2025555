# 수집 후보의 복합 콘텐츠 식별과 최종 출력 원장 대조

- 날짜: 2026-08-23
- 상태: 채택

## 배경

기존 후보 ID와 첫 번째 중복 규칙은 정규화한 원본 URL과 이벤트 날짜를 핵심 키로 사용했다. 이는 같은 게시물을 반복 수집해도 완료 상태를 되살리거나 같은 일정을 다시 만들지 않게 하는 안전장치였다. 그러나 월간 일정표·프로필·고정 게시물처럼 링크를 재사용하는 수집원에서는 같은 URL과 날짜가 서로 다른 이벤트 내용을 가질 수 있다. 또한 운영 결과 대조 대상이 `events`와 `scraped_events`로 한정돼, 이미 `board_posts`에 발행한 운영 안내가 신규 후보로 다시 나타났다.

## 결정

URL은 단독 식별자가 아니라 출처 증거로 사용한다.

1. 같은 URL과 날짜라도 정규화한 제목·활동 유형·장소·DJ·근거 내용이 호환될 때만 같은 발생 건으로 판정한다.
2. 같은 결정론 ID가 서로 호환되지 않는 내용을 가리키면 기존 행을 덮어쓰지 않고 콘텐츠 판별자를 포함한 안정적인 보조 ID로 분리한다. 이후의 호환되는 재수집은 그 보조 ID를 다시 사용한다.
3. 한 수집 배치 안에서도 같은 기본 ID의 호환 후보만 합치고, 다른 DJ 또는 다른 이벤트 내용은 모두 보존한다.
4. 최종 출력 대조에는 운영 일정뿐 아니라 게시판 발행물도 포함한다. 게시판 대조는 운영성 요금 안내에 한정하고, 호환 제목과 로컬 원본의 정규화 이미지 유사도가 동시에 고신뢰일 때만 중복으로 판정한다. URL 또는 이미지만으로는 게시판 중복을 만들지 않는다.
5. 운영 감사도 URL·날짜 그룹을 그대로 중복으로 세지 않고 콘텐츠가 호환되는 쌍만 중복 위험으로 보고한다.

## 소유권과 재사용

- 공통 텍스트 정규화·유사도·콘텐츠 호환·충돌 ID 책임은 `server/cafe24/ingestion-duplicate-identity.js`가 가진다.
- 레거시 수집 API와 Ingestor V3는 같은 공통 판정기를 사용한다.
- 이미지 읽기·Sharp 런타임·업로드 경로 해석은 기존 소유자인 `server/cafe24/function-api.js`를 재사용한다.
- 기존 `scraped_events` 상태, `registered_event_id`, `events`, `board_posts`를 사용하며 새 테이블·큐·상태값·특정 게시물 예외는 추가하지 않는다.

## 유지하는 불변조건

- 실제 등록 일정 ID가 있는 완료 후보는 재수집으로 완료 해제하지 않는다.
- 날짜·장소·활동·DJ가 일치하는 소셜과 운영 일정의 고신뢰 중복은 계속 차단한다.
- DJ가 다르거나 활동·제목이 다른 같은 링크의 이벤트는 합치지 않는다.
- 게시판에 같은 포스터가 있다는 이유만으로 실제 소셜·행사·강습 후보를 차단하지 않는다.
- 중복·제외 판정은 원장에서 상태와 근거를 보존하며 데이터를 삭제하지 않는다.

## 롤백

공통 판정기 연결과 게시판 대조 호출을 되돌리면 이전 URL·날짜 중심 동작으로 복귀한다. 콘텐츠 충돌로 생성된 후보는 독립 원장 행이므로 롤백 시에도 삭제하지 않고 관리자 검토 대상으로 남긴다. 운영 원장 보정은 적용 전 생성하는 JSON 백업으로 각 후보 상태를 복구할 수 있다.
