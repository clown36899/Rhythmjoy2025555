# 자유게시판 게시 방식 단일 선택

- 날짜: 2026-08-21
- 상태: 승인, 구현 완료, 배포 전
- 후속 대상: `2026-08-21-free-board-anonymous-authorship.md`의 복합 선택 UI

## 배경

자유게시판 글쓰기의 `is_anonymous`·`is_hidden`·`is_notice`는 각각 작성자 표시, 본문 접근 범위, 게시판 상단 표시를 담당하는 기존 저장값이다. 서버는 과거 또는 외부 입력에서 복합값이 들어와도 비공개 보호를 우선 적용할 수 있어야 하지만, 일반 작성 화면에서 여러 게시 방식을 동시에 선택하게 하면 카드형 선택 UI의 의미와 저장 결과를 사용자가 예측하기 어렵다.

게시 모달과 본문 편집기는 우연히 같은 `.universal-editor-container` 클래스명을 사용했다. 또한 제한 높이의 flex 스크롤 영역에서 직접 자식이 축소될 수 있어, 카드의 실제 내용이 할당 높이를 넘어 편집기 위로 그려졌다.

## 결정

1. 글쓰기 UI는 `일반 공개`, `익명`, `비공개`, 관리자용 `공지`를 같은 이름의 라디오 그룹으로 제공하며 항상 정확히 하나를 선택한다.
2. 선택한 방식은 새 스키마 없이 기존 세 불리언으로 변환한다. 일반 공개는 모두 false이고, 나머지는 대응 값 하나만 true이다.
3. 수정 대상에 복합값이 이미 있으면 공개 범위를 넓히지 않도록 `비공개 → 공지 → 익명 → 일반 공개` 순서로 한 방식을 결정한다. 저장 시 이 결과로 세 값을 정규화한다.
4. 서버 조회 경계는 레거시 복합값 지원과 비공개 우선 보호를 계속 유지한다. 운영 데이터 일괄 변환이나 DB 제약은 추가하지 않는다.
5. 게시 모달은 `.universal-post-editor-container`를 소유하고, 본문 편집기의 `.universal-editor-container`와 CSS 책임을 분리한다. 모달 본문은 각 폼 구역의 자연 높이를 유지하고 전체 본문만 스크롤한다.

## 결과와 롤백

- 일반 글과 건의 작성의 기존 기본값, 익명 마스킹, 비공개 접근 제한, 공지 정렬과 관리자 권한은 바뀌지 않는다.
- 외부 또는 구버전 클라이언트가 만든 복합값도 서버에서 계속 안전하게 읽을 수 있다.
- UI 변경을 롤백해도 저장 구조나 마이그레이션이 없어 데이터 변환은 필요하지 않다. CSS 클래스도 편집기 내부 소유 클래스와 독립적이므로 모달 변경만 되돌릴 수 있다.
