# 수집 후보 자동등록 경계

- 날짜: 2026-07-28
- 상태: 구현

## 배경

기존 수집기는 후보에 `auto_registration.ready`를 계산했지만 후보 저장과 실제 일정 등록 API가 분리되어 있어 자동등록이 일어나지 않았다. 과거에는 실제 일정 ID 없이 후보만 완료 처리된 기록도 있어, 수집기 판정만으로 완료 상태를 변경하는 방식은 사용하지 않는다.

## 결정

자동등록은 다음 두 단계를 모두 통과한 후보에만 적용한다.

1. 수집기가 원문에서 날짜, 제목, 활동 유형, 장소, DJ를 추출하고 출처별 규칙을 통과시킨다. 이미지는 소셜 이외 활동에 필수이며 소셜에는 선택 사항이다.
2. AI 판정기가 원문만 입력받아 후보의 날짜, 활동 유형, 장소, DJ를 독립적으로 구조화하고 원문에 실제 존재하는 근거 문구를 반환한다.
3. 수집기는 AI와 기존 추출값이 전부 일치하고 신뢰도가 0.98 이상이며 모든 근거 문구가 원문 부분문자열이고 근거 안에 날짜·장소·각 DJ·활동 유형이 명시될 때만 자동등록 준비 상태를 유지한다.
4. 서버가 저장된 후보를 다시 읽어 AI 판정, 원문 근거, 허용 출처/활동, 날짜 형식, 장소, DJ, 활동별 이미지 정책, 대기 상태를 독립적으로 재검증한다.

서버 허용 범위는 경성홀, 스윙스캔들, 네오, The Social Club, 스윙타임, 스윙타운,
스윙프렌드(공식 카페·Instagram)의 명시된 활동군으로 한정한다. 스위티스윙과
그 밖의 출처는 후보 수집만 허용하고 자동등록하지 않는다. The Social Club은
수요일 소셜만 허용한다. 스윙타운의 고정 장소는 `봉천살롱`, 스윙프렌즈의 기본
장소는 `스윙타임`으로 검증한다. 스윙프렌즈 토요일 해피홀 일정처럼 원문 또는
포스터에 다른 장소가 명시되면 고정값보다 명시 장소를 우선해 별도 일정으로
처리한다. 단체명 자체를 장소로 쓰는 후보는 허용하지 않는다. 시간 정보는
수집·판정·등록 대상이 아니며, 시간 필드가 포함된 후보는 자동등록에서 제외한다.
자동등록 성공 시에만 실제 일정 ID를 후보에 연결하고 완료 상태로 바꾼다.

AI는 웹 접근이나 등록 권한을 갖지 않고 수집된 원문의 두 번째 판정기로만 사용한다. 모델 호출 실패, 0.98 미만, 복수 일정 혼합, 수집기와 불일치, 원문에 없는 근거 중 하나라도 발생하면 자동등록하지 않고 수동 후보로 남긴다. AI의 자신감 값만으로 등록하지 않으며 최종 등록 권한은 결정적 서버 검증에 둔다.

## 검증

- 자동등록 허용 후보와 차단 후보 단위 테스트
- AI 합의, 환각 근거, 날짜/활동/장소/DJ 불일치 단위 테스트
- 실제 모델 명확 후보 승인 및 복수 날짜·DJ 혼합 후보 차단
- 수집 표준 검사
- 같은 표준·AI·서버 차단 테스트 10회 반복
- 프로덕션 빌드

## 2026-07-30 날짜 전용 정책 보강

- 당일 일정도 날짜가 오늘이면 수집 가능하다. 시작 시간 존재 여부나 현재 시각과의 비교로 후보를 거부하지 않는다.
- 수집 후보의 `time`과 `times`는 최종 구조화 데이터에서 제거한다. 서버는 직접 주입된 시간 필드를 계속 거부해 날짜 전용 계약을 유지한다.
- 공식 단일 장소 소스가 레지스트리 고정 장소를 사용한 경우 AI와 서버는 `검증된 공식 수집원 고정 장소` 문장을 장소 근거로 사용할 수 있다. 이 근거는 날짜·DJ·활동 유형 증거로 사용할 수 없다.
- 스윙타운은 `봉천살롱`, 스윙프렌즈는 `스윙타임`을 공식 기본 장소 근거로 사용한다. 원문 또는 포스터에 `해피홀` 등 다른 장소가 명시된 후보는 명시 장소를 우선하고, 레지스트리 장소를 쓰는 후보는 설정된 고정값과 정확히 일치해야 한다.
- 이미 자동등록된 후보가 같은 원본 URL·날짜·등록 일정 ID를 유지하면서 더 정확한 값으로 다시 수집되면, 새 후보가 현재 자동등록 안전 검증을 모두 통과하는 경우에만 기존 일정을 갱신할 수 있다. 출처나 날짜가 달라지거나 등록 일정 연결이 없는 완료 후보는 다시 열지 않는다.
- 과거 버전이 등록 일정 ID를 기록하지 않은 완료 후보는 예외적으로 원본 URL과 날짜가 정확히 같은 운영 일정이 단 하나 존재하고, 새 후보가 현재 자동등록 안전 검증을 전부 통과할 때만 다시 열 수 있다. 일치 일정이 없거나 둘 이상이면 자동 복구하지 않는다.

## 2026-08-02 소셜 날짜·DJ 우선 및 이미지 선택 정책

- 자동등록 허용 공식 출처의 소셜은 미래 날짜와 날짜별 DJ가 원문에서 명확하고, 출처별 장소 정책과 AI 0.98·서버 재검증을 통과하면 이미지가 없어도 자동등록할 수 있다. 이미지 필수 조건은 소셜 이외 활동에 유지한다.
- 한 게시물에 다른 날짜의 파티·강습 문구가 함께 있어도 완결된 날짜/DJ 대응 구간은 한 건부터 독립 소셜 후보로 분리한다. 묶음 날짜 머리글은 해당 요일/DJ 구간과 함께 증거로 저장하며, 다른 날짜의 활동 문구는 후보 증거에서 제외한다.
- `swingtimebar` 공식 Instagram은 고정 장소 `스윙타임`, 자동등록 활동 `social`로 허용한다. 날짜·DJ 추측, 불완전한 대응, AI 불일치, 시간 필드가 있는 후보는 계속 자동등록하지 않는다.

## 2026-08-03 검색 발견 후보 수동 검수 정책

- 실제 원문이 자동등록 허용 공식 계정에 속하더라도 `benefit_search`를 통해 발견한 후보는 자동등록하지 않는다. 검색 결과 순위, 스니펫, 오래된 색인과 원문 접근 상태가 직접 소스 순회보다 불안정하기 때문이다.
- 후보는 실제 원문 출처와 별도로 `discovery_source_id`, `discovery_source_type`을 보존한다. 수집기 준비 판정과 서버 등록 판정이 이 발견 경로를 각각 검사하며, 어느 한쪽이라도 `benefit_search`이면 관리자 검수 대기로 남긴다.
- 무료·할인·정기권은 `benefit_kind`로 분리하지만 별도 운영 이벤트나 쇼핑 상품을 자동 생성하지 않는다. 승인 시 기존 일정 등록 경로를 사용하고, 쇼핑 데이터 연계는 별도의 소유권·중복·상품 수명 정책이 마련되기 전까지 읽기/쓰기 모두 분리한다.

## 2026-08-03 혜택 AI 판단과 등록 권한 분리

- 혜택 후보는 자동등록 준비 여부와 무관하게 AI가 원문 근거, 혜택 종류, 현재 유효성, 종료일, 기본 분류를 다시 판단한다.
- AI가 확인한 결과는 후보 품질 판정과 관리자 검수 보조에만 사용한다. `benefit_search` 발견 후보의 수동 검수 정책을 해제하거나 운영 일정을 자동 생성하는 권한으로 사용하지 않는다.
- 원문에 정확히 근거한 0.98 이상 명백한 거절만 저장 전에 제외한다. 승인 결과는 `AI 확인`, 불일치·애매함은 `AI 재검토`, 실행 실패는 `AI 오류`로 보존한다. AI 실행 실패 때문에 결정적 검증을 통과한 후보 자체를 유실하지 않는다.
