# 자동등록 장소 연결의 공통 소유권

- 날짜: 2026-09-16
- 상태: 95da66e3 운영 배포·15건 연결 복구 완료. 미확정 10건 자동 연결 제외.

## 결정

관리자 매핑의 src/utils/venueNormalization.ts 구현을 같은 위치의 venueNormalization.mjs로 이동하고 기존 TS 모듈은 호환 진입점으로 유지한다. 수집기의 별칭 테이블과 한글/영문 정규화도 이 모듈을 재사용한다. 브라우저·Node 서버가 같은 구현을 사용할 수 있도록 하기 위한 이동이며 두 번째 매칭 구현을 만들지 않는다.

자동등록 서버는 후보 검증 이후, 중복 판정 이전에 기존 장소 목록을 대조하여 venue_id/address/location_link를 채운다. 수동 검토 경로의 유사 이름 검색은 유지한다. 자동 경로는 strict 옵션으로 비활성·동명·부분 이름·없는 명시 ID의 추정 연결을 피한다. 등록된 지도 URL 파싱은 기존 우선순위(카카오/네이버/구글)를 그대로 사용한다. 장소가 등록되지 않았거나 명확하지 않으면 추출 원문을 그대로 보존한다.

## 기존 데이터 복구

장소 정보 복구용 기존 운영 도구가 없어 검토된 ID 쌍만 받는 backfill-ingested-event-venues.mjs를 둔다. 이는 운영 복구 진입점이며 매칭/저장은 공용 구현과 기존 saveCafe24TableRow가 소유한다. 신규 SQL 저장 경로나 정기 작업은 없다. 등록 원장 연결과 미연결 상태를 확인하고, 0600 백업 뒤 기존 이벤트 잠금 아래 동시 변경 여부를 재확인한다. 관계없는 이벤트 필드·원문 증거·알림은 바꾸지 않는다.

스키마 이관은 없고 코드 되돌리기와 백업 원본 복원이 롤백 방법이다. 테스트는 기존 관리자 매핑·서버 등록·잠금 회귀를 확장하며 운영 가짜 일정 등록은 하지 않는다.
