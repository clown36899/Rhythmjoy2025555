# 자유게시판 익명 작성자 정보 소유와 노출 경계

- 날짜: 2026-08-21
- 상태: 승인, 구현 완료, 배포 전

## 배경

자유게시판에는 글 내용 전체를 작성자와 관리자에게만 보여주는 `is_hidden` 보호가 이미 있다. 새 요구사항은 글은 공개하되 게시판의 작성자 표시만 익명으로 만드는 것이므로, 기존 비공개 의미를 바꾸거나 별도 게시판·별도 작성자 저장소를 만들면 안 된다.

게시글은 `generic_records`의 `board_posts` 레코드 `data_json`에 저장된다. 이 구조는 게시글별 선택 속성을 수용하므로 익명 전용 테이블이나 DB 마이그레이션은 필요하지 않다.

## 결정

1. `board_posts.data_json.is_anonymous`를 공개 글의 작성자 노출 정책으로 사용한다. 필드가 없거나 false이면 기존 표시를 유지한다.
2. 실제 `user_id`, `author_name`, `author_nickname`은 기존 게시글 레코드에 그대로 보관한다. 관리자 조회와 게시글 소유권 검사는 이 원본을 사용한다.
3. 서버 조회 경계에서 익명 작성자를 가린다.
   - 관리자: 저장된 작성자 ID·이름·프로필을 반환한다.
   - 작성자 본인: 화면 이름은 `익명`으로 바꾸고 프로필을 제거하되, 기존 수정·삭제 소유권 동작을 위해 본인의 `user_id`만 유지한다.
   - 게스트와 다른 사용자: 화면 이름은 `익명`으로 바꾸고 `user_id`, 프로필 이미지, 작성자 프로필 관계를 제거한다.
4. 작성자 관련 필터로 원본을 추론하지 못하도록 `board_posts`는 기존과 같이 호출자 필터보다 먼저 서버에서 정제하고, 관계 데이터 결합 뒤에도 다시 정제한다.
5. `is_hidden`과 `is_anonymous`는 독립된 불리언이다. 둘 다 true일 수 있으며, 이 경우 기존 비공개 보호가 먼저 적용되어 권한 없는 사용자에게 제목·본문·작성자와 익명 여부를 반환하지 않는다.
6. 목록과 상세 UI도 공통 표시 함수를 사용해 비관리자에게 `익명`을 렌더링하고 프로필 이미지를 숨긴다. 서버가 최종 보안 경계이고 UI 처리는 중복 방어다.

## 결과와 롤백

- 기존 비공개·공지·머릿말·게시글 소유권 구조와 별도 익명게시판은 변경하지 않는다.
- 관리자 편집 시 익명 글의 저장된 작성자 이름을 `관리자`로 덮어쓰지 않는다.
- 롤백 시 UI 옵션과 마스킹 연결을 제거해도 기존 레코드는 유효하다. 저장된 `is_anonymous` 값은 미사용 JSON 속성으로 남으므로 데이터 변환이나 파괴적 롤백이 필요 없다.
