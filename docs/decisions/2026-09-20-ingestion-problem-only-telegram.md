# 수집 주기 유지와 문제 중심 텔레그램 안내

- 날짜: 2026-09-20
- 상태: 로컬 LaunchAgent 실행기에 적용 완료. 수집·사이트 배포·운영 이벤트 데이터 변경 없음.

## 검토 근거

설치된 LaunchAgent는 우선순위 1·2 각각 하루 13회, 혜택 검색 3·4 각각 하루 1회로 총 28회 실행된다. 1·2의 전체 수집은 각각 하루 5회이며 중간 16회는 당일 미확정 소셜 복구 확인이다. 미확정 대상이 없으면 브라우저를 열지 않고 종료한다. Codex의 별도 post-run repair 자동화는 PAUSED이며 구형 Claude LaunchAgent도 비활성이다.

9/16~19의 112회 기록에서 실제 소스를 읽는 실행은 하루 12회, 대상 없는 확인은 하루 16회였다. 확인은 약 5~6초, 전체 일일 실행 시간은 약 128~138분, 최장 실행은 15.3분이었다. 중복 잠금 차단·강제종료는 없었다. 종료 75의 44회는 남은 소스가 있는 부분 완료이며, 로그인 제한·AI 추출 검토·자동등록 보류가 주된 원인이다. 전체가 정상 완주했다는 뜻은 아니다.

같은 기간 후보 신규 저장 16회, 공개 등록 11회·기존 보정 43회가 보고됐다. 등록/보정의 고유 이벤트 ID는 16개이며 공개 API에서 15개를 확인했다. 나머지 하나는 9/16 사보이 중복 정리 기록의 삭제 ID이고, 보존한 DJ 단미 일정이 공개돼 있다. 자동등록 횟수를 신규 이벤트 수로 해석하지 않는다. 인스타그램 로그인 제한과 AI 가용성·원문 검토 문제는 별도로 남아 있다.

기존 설치 실행기의 `telegram_notify`는 수집 시작과 종료마다 호출돼 9/16~18 각 56회, 9/19에는 성공 55회·실패 1회 전송됐다. 대상 없는 확인에도 두 번 발송하는 것이 안내 과다의 공통 원인이다.

## 결정과 소유권

기존 구현은 일부 있음이다. 단일 발송 함수·수집 결과 JSON·실행별 메타 파일·공통 실행 잠금은 있고, 정상 안내 제외 및 같은 문제 중복 억제는 없었다. 수집 주기·대상·AI 기준·완료 체크포인트·동일 날짜/장소 충돌 보류를 유지한다. 이미 수집하지 않는 가벼운 확인을 제거하면 당일 미확정 일정의 복구 기회를 줄일 수 있어 이번에는 변경하지 않는다.

- `scripts/ingestion/telegram-notify.sh`가 설치 실행기의 기존 전송 함수를 옮겨 소유한다. 별도 봇·전송 경로를 추가하지 않는다.
- `telegram-notification-policy.mjs`는 시작/정상 완료를 제외하고, 접근 제한·저장/등록 미완료·프로세스 실패·결과 누락을 판정한다. 정상 exit 0이라도 구조화된 문제가 있으면 알린다.
- 같은 프로필·우선순위·소스·단계·문제 종류는 성공 전송 후 24시간 동안 다시 보내지 않는다. 바뀌는 AI 문장·날짜·후보 ID 때문에 같은 문제가 새 알림이 되지 않게 한다. 새 소스/종류의 문제는 즉시 대상이 된다. 정상 확인 실행은 과거 문제 기록을 초기화하지 않는다.
- 기존 `*.meta`에 `telegram_notified_at_ms`와 `telegram_problem_keys`만 추가한다. 기존 완료/읽음 시각에는 전송 성공 여부가 없어 별도 필드가 필요하다. 새 원장·테이블·큐·수집 체크포인트는 만들지 않는다. 기존 실행 잠금 안에서 판정→전송→기록을 순서대로 처리한다.
- 전송 실패·설정 누락·dry-run은 성공 기록을 남기지 않아 다음 회차에서 재시도할 수 있다. 요약은 3,500자 이내로 줄이고 전체 수집 결과는 기존 실행 로그에 보존한다.

## 적용과 롤백

`node scripts/ingestion/install-telegram-policy.mjs`는 기본 읽기 전용 점검이다. `--apply`는 알려진 기존 전송 함수와 10개 호출부만 연결하며 모르는 구조는 거부한다. Bash 구문 확인 후 파일을 원자적으로 교체해 실행 중인 작업을 끊지 않는다. 재실행은 변경 없음이다. 설치 당시 실행 중인 수집 프로세스는 없었다.

설치 실행기 `/Users/inteyeo/scripts/run-ingestion.sh`의 원본은 같은 디렉터리 `run-ingestion.sh.bak-telegram-policy-1789890842342`에 0600으로 보관했다. 기존 즉시 전송으로 복귀하려면 환경의 `INGESTION_TELEGRAM_MODE=all`을 사용할 수 있다. 코드 자체 롤백은 원본 실행기를 원자적으로 복원하면 된다. 봇 토큰·채팅 대상은 변경하거나 문서에 기록하지 않았다.

## 검증과 범위

정상/신규 저장 안내 제외, exit 0 문제, 결과/요약 누락, 비정상 종료, 24시간 경계, 새로운 소스/종류, 바뀐 AI 문장/후보 ID, legacy Codex 요약, 실패·설정 누락·dry-run의 재시도 보존, 실제 shell gate의 성공 기록, 설치 연결/멱등성을 검증했다. 기존 잠금·자동등록 보고 검사와 수집 표준 검사도 재사용했다.

9/16~19 기록을 시간순으로 재생한 계산에서는 하루 알림이 8·6·7·5회였다. 실제 향후 발송량 보장이 아니며, 재생 과정에서 텔레그램을 보내거나 운영 로그를 바꾸지 않았다. 검증을 위한 전체 실수집·AI 재호출·운영 게시글 쓰기는 필요 없어 제외했다. 사용자에게 테스트 메시지를 보내지 않았다. 정책 적용 후 최초 실제 예약 실행의 전송 결과는 이 작업 시점에는 아직 확인 전이다.
