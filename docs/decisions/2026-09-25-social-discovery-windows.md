증상 → 판정 → 실행 → 원장: 기존 31개 예약은 이미 복구됐지만 `isSupplementalRecoveryRun`이 `lastDiscoveryAt`의 KST 날짜만 비교 → 같은 날 12/16/18/20시의 설정도 모두 당일 보충 모드 → 오늘 정규 소셜이 완료돼 있으면 브라우저를 열지 않음 → 오후에 새로 올라온 미래 주간 일정은 다음 날까지 탐색 불가. Mini PC의 실제 priority1/2 `lastDiscoveryAt`은 각각 9/25 08:00, 09:00이며 저녁에도 새 탐색이 선택되지 않던 조건이었다. 이 사실을 이전 사보이 날짜 오추출·해피 URL 완료 오판과 동일 원인이라고 단정하지 않는다.

기존 구현은 **일부 있음**. `INGESTION_NATIVE_FULL_SCAN_HOURS`, `lastDiscoveryAt`, `completedItems`, `deferredItems`, `findUnresolvedTodaySocialSources`와 기존 main을 재사용한다. 정확한 빈틈은 ‘미완료 항목 반복 제한’을 ‘새 공지 탐색 하루 한 번’으로 연결한 날짜 비교다. 이 함수의 해당 줄은 미커밋 변경이며 최초 목적은 9/23 당일 재시도 결정 기록에서 확인했다. `dcd369e0`의 재개/중복 처리 축소, `fe2b77c6`의 실패 시 완료 전진 방지 목적을 관련 diff와 대조했다. 새 함수·필드·DB·큐·상태·예약은 추가하지 않는다.

## 현재 정책

- 소셜·휴무 수집, 후보 저장, 자동등록과 당일 재시도를 다시 활성화한다. 기존 레지스트리 정책 한 곳이 수집기·등록 서버·감사를 함께 제어한다.
- priority1의 08/12/16/18/20시, priority2의 09/13/17/19/21시를 각각 탐색 시간대로 사용한다. 실제 예약 분은 그대로 유지한다. 현재 시각과 직전 탐색 시각이 서로 다른 시간대면 새 탐색, 같은 시간대면 오늘 미완료만 재시도한다.
- 지연 기동은 현재 시간대 한 번으로 따라잡는다. 놓친 예약별 연속 실행, 일부 실패를 이유로 모든 출처 즉시 재시작, 예약 횟수 추가는 하지 않는다.
- 완료 문서·후보는 재추출/재저장하지 않는다. 내용이 같은 미래 실패는 행사일까지 보류하고, 과거 실패는 종료한다. 당일 실패는 다음 기존 예약에서 재시도하고 공개 등록·확정 휴무·관리자 삭제 후 멈춘다. 확인한 근거가 바뀌면 기존 내용 지문이 구분한다.
- 원문 근거, AI 검증, URL/날짜 동일성, 같은 장소·날짜 충돌 검토 및 쓰기 잠금은 그대로다. 수동/설정 없는 레거시 실행은 기존 탐색을 유지한다. 원장 조회 실패를 오늘 대상 0으로 취급하지 않는다.
- UI는 자동수집 안내와 큰 ‘공식 공지 확인’ 버튼을 함께 제공한다. 개별 등록 원문은 별도 링크로 남긴다. 정규 생성본의 ‘정규 요일’은 당일 공지 확정과 구분하며, 휴무/등록본/명시 DJ를 기본 안내로 되돌리지 않는다. 시간 전용 정보와 드래그 동작은 추가하지 않는다.

## 검증·운영 경계

실제 native 메인과 기존 검사를 확장해 같은 시간대 무탐색, 다음 시간대 새 미래 공지 발견, 성공 형제 재저장 없음, 미래 실패 보류, 422/503 당일 실패→다음 예약 성공→이후 브라우저 0을 연결했다. 날짜 전후·자정·다음 주·휴무·관리자 삭제·원장 조회 실패, 서버 수동/자동·중복 충돌·같은 이벤트 재시도도 기존 검사를 재사용한다. 저장 구조가 그대로라 DB 마이그레이션과 원장 초기화는 제외한다.
