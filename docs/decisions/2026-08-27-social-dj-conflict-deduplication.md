# 소셜 DJ 불일치와 후보 중복 재판정

## 상태

2026-08-27 채택.

## 배경

수집 후보 중복 판정은 날짜·장소·활동·DJ가 같은 소셜을 교차 출처 중복으로 막는다. 다만 이 엄격한 판정 뒤에 일반 이벤트용 유사 제목·장소 규칙이 계속 실행돼, 양쪽에 확정 DJ가 있고 값이 다른 소셜도 중복으로 되었다. 이로 인해 수동 대기 중인 OCR 후보가 나중에 확인된 공식 자동등록 후보를 막을 수 있었다.

## 결정

양쪽이 모두 소셜이고 알려진 DJ 명단이 모두 있지만 서로 다르면, 날짜·제목·장소·출처 유사도만으로는 중복 처리하지 않는다. 외부 공식 API 일정 우선과 같은 DJ 명단의 고신뢰 소셜 중복은 유지한다.

이전 규칙으로 종결된 후보를 일반적으로 다시 열지 않는다. 같은 원문·날짜의 재수집 결과가 서버 자동등록 관문을 완전히 통과하고, 기존 중복 대상이 아직 미완료 후보이며, 현재 중복 규칙으로 다시 대조했을 때 일치하지 않는 경우에만 기존 `duplicate`를 `pending`으로 재판정한다. 기존 상태값과 저장 경로를 재사용하며 새 원장이나 상태를 만들지 않는다.

## 불변조건과 영향

- 날짜·장소·활동·DJ가 모두 같은 소셜은 계속 중복으로 차단한다.
- 외부 공식 API 일정은 기존처럼 우선하고, 등록 완료·제외 상태와 등록 연결이 있는 후보는 재개하지 않는다.
- DJ 중 하나라도 미정이거나 비어 있으면 불일치를 근거로 자동 분리하지 않고 기존 보수적 규칙을 유지한다.
- 개별 날짜·게시물·DJ 예외와 새 DB 필드·테이블·큐·상태값을 추가하지 않는다.
