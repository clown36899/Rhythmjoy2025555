# 같은 날짜·장소 소셜의 자동등록 충돌 재검토

- 날짜: 2026-09-16
- 상태: 운영 배포·중복 5건 복구 완료 (f67224e4)

## 조사와 기존 보호 목적

원본 수집 → 후보 콘텐츠 ID 판정 → 자동등록 → events/후보 완료 연결/알림 생성 경로를 확인했다. 9월 공개 일정과 후보 원장을 읽기 전용으로 대조한 결과, 9/6·9/16·9/17·9/19의 5그룹이 중복이었다. 같은 포스트의 DJ 판독이 `몽룡`/`77L 주스 몽룡`, `단미님`/`77L 주스 단미`, `PM8`/`민·캐롤`로 갈리거나, 교차 출처에서 DJ를 누락한 후보가 추가 등록됐다.

- e3f76dc3: 확정 날짜·장소·활동·DJ가 같은 교차 출처 중복 방지.
- 8c5d1a70: 같은 링크에 실린 서로 다른 행사를 잃지 않도록 콘텐츠 ID 분리.
- ec0a7be1: DJ가 다른 실제 소셜을 일반 제목 유사도만으로 합치지 않는 보호.
- 542e6e7d: 관리자 삭제를 자동으로 복구하지 않게 하는 기존 일정 쓰기 잠금.

문제는 ‘확정 중복이 아님’을 바로 ‘추가 자동등록 가능’으로 처리한 연결 누락이었다. 후보 분리 자체나 서로 다른 DJ 원문을 보존하는 기존 목적은 유지한다.

## 결정과 소유권

기존 구현 일부 있음. function-api의 날짜·장소·소셜 분류·기본 일정 교체 판정과 pending/auto_registration.reasons를 재사용해 충돌이면 422로 자동등록을 보류한다. 기존 관리 검토함에서 원문을 비교할 수 있도록 보류 이유와 기존 일정 ID/제목을 표시한다. 새 상태·테이블·큐·수집기 없음.

엄격한 확정 중복은 계속 duplicate로 처리한다. 같은 일정 보정은 자기 ID를 제외하며, DJ 미정 정규 기본 일정은 기존 실제 공지 교체 흐름을 유지한다. 강습·행사·다른 날짜·다른 장소에는 적용하지 않는다. 관리자가 검토한 수동 등록 권한은 유지한다. 이 규칙은 8/27의 DJ 충돌 보호를 삭제하지 않고 자동등록 전 재검토를 추가한다.

동시 요청에 대해서는 generic-data-api의 기존 withEventMutationLock 안에서 등록 전 검사를 다시 실행한다. 서버 내부 선택 인자 beforeEventSave와 기존 loadRows의 executor 인자로 같은 연결을 재사용한다. 별도 잠금 소유자나 중복 SQL 저장 구현을 만들지 않는다. 콜백은 요청 JSON에서 받지 않는다.

## 운영 정리와 롤백

기존 reconcile-2026-08-12-swingtime-duplicate.mjs를 재사용하고, 확인한 원문에 따른 --plan 인자만 확장한다. 원래 기본 실행과 고신뢰 판정, 관계/관심 등록 검사, 원본 백업, 트랜잭션, 후보 이력·이미지·발송 원장 보존을 유지한다. 다른 DJ 표기의 수동 확인 계획은 같은 발생 날짜/장소와 정확한 후보 등록 ID를 다시 검증한다. 관리자 삭제 표식은 해당 장소의 정상 행사까지 막으므로 중복 정리에는 생성하지 않는다. 기존 duplicate 참조도 유지 일정으로 바꿔 끊어진 원장 참조를 남기지 않는다.

검토 결과 중복 5건만 정리하고 사보이 9/19 제목/후보 DJ를 원본 포스터의 단미로 보정한다. 설명과 이미지 속 시간 문구는 변경하지 않는다. 스키마 이관은 없으며 코드 롤백은 커밋을 되돌리고, 데이터 롤백은 보호된 백업의 원본 행을 복원한다.

## 검증 범위

기존 등록 연계·원장·정규 소셜·관리자 삭제 회귀검사를 확장했다. HTTP 경로의 보류/수동 등록/동시 등록/같은 일정 재시도, 잠금 안의 검사 실패 시 이벤트 INSERT와 알림 미발생, 잠금 해제, 개별 회차 날짜, 장소 ID/별칭, DJ 누락/변경을 검증한다. 표준 수집 검사와 프런트 빌드도 실행한다. 외부 AI 전체 수집이나 운영 테스트 이벤트 추가는 범위 밖이며 저장된 실제 원문·포스터와 복구 가능한 dry-run으로 검증한다.
