# Project Record Keeping

- 날짜: 2026-07-14
- 상태: accepted

## Context

프로젝트에는 이미 여러 기록이 남아 있다. Git 커밋 히스토리, `CHANGELOG.md`, Cafe24 문서, 수집 자동화 현황 문서, 키오스크 작업 로그, 코드 리뷰 보고서가 각각 일부 맥락을 보유한다.

하지만 이슈, 장애, 원인 분석, 해결 방법이 한곳에 모이지 않아 과거 판단을 다시 찾기 어렵다. GitHub Issues와 PR 목록도 현재 비어 있어, 저장소 안 문서를 기록의 중심으로 삼는 편이 즉시 적용 가능하다.

## Decision

앞으로 프로젝트 기록은 다음 기준으로 남긴다.

- `docs/ISSUE_LOG.md`: 버그, 장애, 운영 문제, 조사, 해결, 검증, 재발 방지 기록
- `docs/decisions/`: 장기 의사결정과 운영 정책 기록
- `CHANGELOG.md`: 사용자에게 보이는 버전별 변경점
- Git 커밋: 실제 변경의 최종 감사 추적

작업자가 볼 수 있도록 `AGENTS.md`에도 기록 기준을 추가한다.

## Consequences

- 문제 해결 과정이 Git 추적 문서로 남는다.
- 이후 작업에서 "어디에 기록해야 하는가"가 명확해진다.
- 단, 모든 사소한 변경까지 기록하면 문서가 소음이 되므로 비 trivial 작업 중심으로 남긴다.
- 비밀번호, 토큰, SSH 키, 쿠키, 운영 `.env` 값은 어떤 기록에도 남기지 않는다.
