# 2026-09-30 원데이 공동 편집과 서버 부분 배포

## 확인한 기존 경계

원데이 등록 모달과 목록은 로그인 회원 누구나 등록·수정·로고 변경을 제공한다. 삭제 버튼만 관리자에게 보인다. 서버 이전 때 추가한 `adminOnlyMutationTables`와 로고 함수의 `requireAdmin`이 이 UI와 불일치했다. 2026-09-30 사용자는 등록자 없는 기존 항목을 포함해 로그인한 회원 누구나 수정할 수 있다고 명시했다.

## 결정

- 원장은 기존 `generic_records`의 `swing_oneday_recruit_links`를 계속 사용한다. 회원별 소유자 필드나 새 테이블·API를 만들지 않는다.
- 기존 `requireLoggedInMutationUser`를 로고 함수에서도 재사용한다. 일반 회원은 insert/update, 로고 업로드·자동 찾기를 사용할 수 있다. 비로그인은 쓰기 불가, 삭제·전체 교체 upsert는 관리자 전용이다.
- 일반 회원의 직접 레코드 쓰기는 화면의 내용 필드로 제한한다. 기존 항목의 활성 상태, 식별자, 로고 저장 메타데이터를 직접 덮어쓰지 못한다. 수정은 단일 ID가 필요하다.
- 기존 저장 함수의 options에 insertOnly를 연결해 회원 신규 등록은 MySQL PK 충돌 시 409로 끝낸다. 사전 조회만으로 충돌을 판정하지 않는다. 기존 레코드·로고 보존과 재시도 경계를 지키며 다른 테이블과 관리자 upsert 동작은 유지한다.
- 회원 로고 업로드는 이미 있는 `normalizeExternalImage`로 검증·WebP 변환 후 저장한다. 새로운 이미지 변환기나 업로드 저장소는 만들지 않는다.

## 배포 경계

현재 원데이 변경 대상 중 운영 `function-api.js`에는 이 작업과 무관한 수집 목록 분기 차이가 있다. 전체 파일 교체나 전체 배포는 그 운영 변경을 덮어쓴다. 기존 배포 명령은 전체·프런트·통계 범위만 있으므로 `--server-patch <base-ref>`를 추가해 기존 검증 절차를 재사용한다.

이 모드는 이미 존재하는 `server/cafe24/*.js` 모듈의 커밋 차이만 운영 사본에 적용한다. 테스트 파일은 제외한다. 새 모듈·패키지·스키마·의존성 추가 배포에는 사용하지 않는다. clean/upstream/main/host 검사를 그대로 통과해야 하며, 무조건 먼저 커밋·푸시한다. 운영 사본에 fuzz=0 패치를 적용하고 문법을 검사한 다음 전송하며, 서버의 원본 해시가 변하면 중단한다. 원본 백업·변경 파일 검증·재시작·health 확인 후 version.json의 serverPatchCommit/serverPatchDate만 마지막에 공개한다. 실패하면 원본 파일과 버전을 복원하고 서비스를 재시작한다. UI buildTime과 다른 운영 파일·DB·cron은 바꾸지 않는다.

롤백은 배포가 남긴 `.deploy-server-<commit>-<epoch>/previous`를 이용한다. 권한을 되돌리면 일반 회원 쓰기는 다시 막히지만 이미 저장된 링크를 삭제하거나 스키마를 되돌릴 필요는 없다.

같은 날 [게시판 새 글 집계 수정](2026-09-30-free-board-visible-unread.md)에서 서버가 직접 import하는 기존 `src/utils/*.mjs`도 같은 패치 대상으로 허용했다. 서버·공용 모듈을 함께 반영해야 하므로 기존 책임의 경로만 확장하며, 새 모듈·의존성 배포 금지와 나머지 검증·복구 조건은 유지한다.
