# PWA 릴리스 일관성 계약

- 날짜: 2026-08-09
- 상태: 운영 적용 및 검증 완료

## 배경

Android Chrome에서 배포 전후의 서로 다른 앱·서비스워커가 동시에 살아 있을 때 다음 두 오류가 반복됐다.

- 앱은 IndexedDB `notification-history` 버전 2를 열지만 서비스워커는 같은 DB를 버전 1로 열어 `VersionError`가 발생한다.
- 배포가 구 해시 자산을 즉시 삭제하고 새 서비스워커가 즉시 활성화·구 캐시 삭제·클라이언트 선점을 수행해, 구버전 탭의 지연 청크 요청이 실패한다.
- 존재하지 않는 `/assets/*` 요청도 SPA fallback이 `index.html`을 HTTP 200으로 반환해 JavaScript 요청 실패가 `Failed to fetch` 또는 모듈 파싱 실패로 왜곡된다.
- PWA 플러그인의 `autoUpdate` 리로드와 앱의 `DeploymentAutoRefresh`가 별도 갱신 주체로 동작한다.

격리 브라우저 실험에서 현재 방식은 신버전 전환 뒤 구버전 탭의 지연 import가 `FAILED:TypeError`로 끝났다. 새 서비스워커를 대기시키고 구버전 자산을 유지한 비교군은 같은 import가 `lazy-1-ok`로 성공했다. 앱 DB v2를 연 뒤 서비스워커 경로가 v1을 열면 `VersionError`, 양쪽이 v2이면 성공하는 것도 재현했다.

## 채택한 불변 조건

1. 배포 순간에도 직전 클라이언트 버전은 정해진 중첩 기간 동안 실행 가능해야 한다.
2. 서비스워커 활성화와 페이지 리로드를 결정하는 주체는 하나여야 한다.
3. 하나의 영속 데이터는 하나의 계층이 소유해야 한다.
4. 정적 자산 실패는 HTML 성공 응답으로 위장하지 않고 정확한 404로 끝나야 한다.
5. 새 릴리스의 모든 자산 검증이 끝나기 전에는 HTML·서비스워커·버전 포인터를 공개하지 않는다.

## 채택 구조

### 릴리스·자산

- 새 자산을 먼저 업로드하고 참조 무결성을 검사한 뒤 진입 파일을 전환한다.
- 직전 2개 릴리스 또는 최소 7일 동안 해시 자산을 보존한다. 매 배포 시 `--delete`로 구 자산을 즉시 지우지 않는다.
- `/assets/*` 미존재 요청은 SPA fallback 앞에서 404로 종료한다.
- 장기적으로는 릴리스 디렉터리와 원자적 `current` 포인터를 사용해 전환·롤백 단위를 일치시킨다.

### 서비스워커·갱신

- `autoUpdate`와 별도 버전 폴러 중 하나만 남긴다. 이 앱에서는 기존 입력·모달 보호를 살릴 수 있도록 `prompt` 등록과 단일 갱신 코디네이터를 권고한다.
- 설치 이벤트의 무조건 `skipWaiting()`과 활성화 이벤트의 무조건 `clients.claim()`을 제거한다.
- 새 서비스워커는 대기하고, 화면이 보이며 입력·모달·중요 작업이 없을 때 코디네이터가 한 번만 활성화와 리로드를 수행한다.
- 전체 JavaScript 청크 프리캐시는 제거하고 설치·Push·공유 대상에 필요한 최소 셸만 캐시하는 온라인 우선 PWA로 단순화한다. 직전 탭 호환성은 서버의 해시 자산 보존 계약으로 보장한다.

### 알림 저장소

- 서버 알림함을 원본으로 유지하고 서비스워커의 `notification-history` 직접 저장·읽음 처리를 제거한다.
- Push 서비스워커는 운영체제 알림 표시와 서버 식별자 전달만 담당한다. 오프라인 임시 저장이 반드시 필요해지면 앱 DB와 분리된 서비스워커 전용 spool DB를 별도 이름·스키마로 둔다.

## 적용 순서

1. 자산 404와 구 해시 보존을 먼저 적용해 구클라이언트 실행 계약을 확보한다.
2. 서비스워커의 알림 DB 소유를 제거한다.
3. PWA 등록을 `prompt`로 바꾸고 갱신·리로드 코디네이터를 하나로 합친다.
4. 두 탭, 숨김 탭, 지연 라우트, 네트워크 단절·복귀, Push 수신, DB 업그레이드 조합을 통과한 뒤 운영에 배포한다.

각 단계는 독립 배포·롤백 가능하게 유지한다.

## 2026-08-10 로컬 적용 결과

- 알림함 영속 데이터 소유자는 서버 `user_notifications` 하나로 통일했다. 앱과 Push 서비스워커의 `notification-history` IndexedDB 접근을 모두 제거했고 관리자 미리보기만 비영속 메모리 저장소를 사용한다.
- 서비스워커 설치 시 자동 활성화를 중단하고 PWA 등록을 `prompt`로 변경했다. 기존 `DeploymentAutoRefresh`의 화면 표시·모달·입력 보호 조건을 단일 활성화 코디네이터에 연결했다.
- 배포는 새 해시 자산을 먼저 전송한 뒤 진입 파일을 전환하며 클라이언트 해시 자산에는 즉시 `--delete`를 적용하지 않는다. 서버는 존재하지 않는 `/assets/*`를 SPA fallback 전에 404로 끝낸다.
- 관련 계약 및 회귀 테스트 18개와 Cafe24 프로덕션 빌드가 통과했다. 생성 서비스워커에도 알림 IndexedDB 접근이 없음을 확인했다.
- 커밋 `ad681a7e`를 `origin/main`에 푸시하고 Cafe24 운영에 배포했다. 공개 버전은 `2026-08-10T03:45:17.762Z`이며 서비스·내부·외부 헬스가 정상이다. 공개 서비스워커에는 알림 IndexedDB 접근이 없고, 새 자산과 구 해시 자산 보존 및 없는 자산의 정확한 404를 외부 요청으로 확인했다.
- 직전 자산의 장기 보존 기간과 정리 작업은 별도 운영 변경으로 남겨 둔다. 현재 정책은 배포 시 구 해시를 즉시 삭제하지 않아 혼합 버전 탭의 실행 연속성을 우선한다.
