# 정규 소셜의 행사 당일 재시도

- 날짜: 2026-09-23
- 상태: 당일 재시도 및 항목별 완료·보류 보호는 유지. **하루 한 번 신규 탐색 제한은 2026-09-25 철회**하고 [기존 탐색 시간대별 한 번](2026-09-25-social-discovery-windows.md)으로 복구했다. 아래 최초 결정의 해당 부분은 현재 정책이 아니다.

사용자의 기준은 수요일 정규 소셜 공지가 화요일에 없더라도 반복하지 않고 수요일에만 수집될 때까지 확인하는 것이다. 목요일부터 지난 수요일을 재시도하지 않으며 다음 수요일은 다른 회차다. 단순 빈도 축소나 모든 실패 출처 재시도는 이 의도를 충족하지 않는다.

기존 운영 일정의 당일 미확정 기본 소셜을 기준으로 하는 `findUnresolvedTodaySocialSources`를 단일 판정자로 유지한다. 보충 실행 대상에 `remainingSources` 전체를 합치던 연결을 제거했다. 등록/휴무/관리자 삭제를 추정으로 되살리지 않는다. 출처를 열기 직전에도 운영 일정을 다시 대조해 다른 출처가 이미 등록한 회차는 멈춘다. 당일 재시도에서는 오늘 소셜 및 휴무만 처리하고 미래 회차/강습/과거를 섞지 않는다. 실행 내 같은 출처 재추가를 금지하고 기존 예약·20분 상한을 유지한다. KST 날짜가 바뀌면 그 실행의 쓰기도 중단한다.

예약 시각은 변경하지 않는다. 하루 최초 신규 확인 시도를 `lastDiscoveryAt`에 기록하고 이후 예약은 당일 재시도에 한정한다. 이는 전체 성공 시각인 `lastCompletedAt`으로 표현할 수 없는 정보다. 늦게 켜지거나 잠금으로 시작이 밀려도 첫 확인을 수행하고, 일부 실패 때문에 같은 날 전체를 재시작하지 않는다. 설정 없는 수동/레거시 실행은 기존 전체 확인을 유지한다.

완료 항목과 구별하기 위해 기존 진행 파일에 `deferredItems`를 둔다. 실패한 소셜 후보와 그 문서의 남은 행사일 목록만 기록하며, 같은 내용의 미래 실패는 당일까지 보류하고 지난 실패는 재시도하지 않는다. 한 문서에 여러 날짜가 있어도 성공 회차를 보존하고 남은 회차 날짜에만 다시 처리한다. 내용/출처 정책이 바뀌면 다른 지문으로 새 확인을 허용한다. 강습 수집을 개강일까지 미루는 정책으로 확장하지 않는다.

두 필드의 소유자는 기존 `ingestion-progress.mjs`와 장르/우선순위별 진행 파일이다. 새 DB·큐·예약 작업은 없다. `remainingSources`는 진행 이력으로 보존하며 그 존재만으로 재시도를 허용하지 않는다. 운영 API 실패 시 빈 목록으로 오인하거나 상태를 지우지 않는다. 완료 기록, 등록 ID·원문 근거·중복 충돌 보호는 유지한다.

레거시 파일은 새 필드를 빈 값으로 읽으며 최초 신규 확인 시부터 기록한다. 이미 실시한 오늘 신규 확인의 소급 표시는 검증된 실행 기록과 기존 잠금을 확보한 경우에만 한다. 이번에는 다른 수집이 잠금을 사용 중이어서 이 보정은 실행하지 않았다. 구버전 복귀 시 새 필드는 무시되며 원장/공개 일정 삭제나 마이그레이션은 없다.

검증은 실제 native 메인/함수를 모의 외부 입출력으로 실행해 전날·당일·다음 날·다음 주, 지연 기동·자정, 성공 후 대체 출처 중지, 공개 API 실패, 다중 날짜 부분 실패/원문 변경과 레거시 호환을 확인한다. 실제 다음 예약의 전체 성공 여부는 별도 운영 결과로 확인해야 한다.
