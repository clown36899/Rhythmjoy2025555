# 소셜은 공식 공지 직접 연결로 안내

- 날짜: 2026-09-25
- 상태: **소셜 중단 결정 철회**. 같은 날 사용자가 자동수집 복구·강화를 지시했다. 공식 공지 연결 UI는 유지하며, 아래는 중단 당시 기록이다. 현재 정책은 [탐색 시간대 복구 결정](2026-09-25-social-discovery-windows.md)을 따른다.

## 맥락과 기존 책임

사용자는 반복되는 소셜 오추출/누락 때문에 자동수집·등록 대신 고정된 공식 출처로 연결하고 그 차이를 이용자가 알게 하도록 요청했다. 처음 제안한 ‘공지 반영’ 표시보다 이 후속 결정을 우선한다. 강습·행사 수집, 기존 일정, 관리자 검토 등록은 유지한다.

증상 → 표시 판정 → 사용자 동작 → 기준 데이터: `getCalendarSocialDisplayText`가 DJ 없는 등록 소셜과 정규 생성본을 빈 보조 문구로 표시 → 상세 제목의 링크는 개별 `link1` 대신 레지스트리 계정/게시판으로 대체 → 이용자가 당일 운영 확정 여부와 원문 근거를 구별하기 어려움. 기존 `link1`, `automation.generated_by/source_id/exception_id/exception_type`, DJ 및 주최 출처 ID와 `collection-registry.mjs`가 기준이다.

기존 구현은 **일부 있음**. 출처 레지스트리, 생성본 표식, 공개 링크, 활동 분류, 서버 자동/관리자 경계는 존재한다. 전역 소셜 중단 정책과 생성본의 안내 의미/두 링크 표시가 연결되지 않았다. 새 DB·큐·등록 상태는 만들지 않는다. 레지스트리에 정책 상수와 활동 허용 함수를 두는 이유는 개별 출처 허용 목록만으로 혼합 강습 글·미처리 소셜 후보·휴무 전용 경로를 함께 막을 수 없기 때문이다. 출처 등록과 수집 실행을 분리하며 목록은 삭제하지 않는다.

`bc71db85`의 미정 DJ 숨김, `a2ca355e`의 휴무 라벨, `ed4182c16`의 출처별 활동 허용, `2d4e23c38`/`1a6211406`의 서버 자동등록 허용 목적을 해당 함수/호출부와 blame에서 확인했다. 기존 원문 검증, 관리자 삭제, 동일 장소 충돌과 쓰기 잠금은 유지한다. 중단 플래그는 그 앞에서 자동 실행만 차단한다. 과거 자동 경로 회귀는 명시적으로 이전 정책을 주입해 보존하고 현재 기본값의 차단 경계를 추가 검증한다.

## 변경

- 캘린더에서 정규 생성본은 ‘정규 요일’과 점선으로 표시한다. 확정 휴무/공식 override와 DJ가 있는 기존 수정본은 정규 기본 안내로 되돌리지 않는다. 등록된 DJ 없는 소셜은 ‘소셜’로 표시한다. 원문이 있다는 이유로 최신 운영 확정이라고 표시하지 않는다.
- 소셜 상세의 제목은 제목 역할을 유지한다. ‘공식 공지 확인’ 버튼과 ‘등록된 일정의 원문’ 링크를 분리하고, 같은 계정/게시판 링크를 원문이라고 중복 표시하지 않는다. Naver 공유 카페는 저장된 출처 ID/주최 ID를 기존 `findSourceForCandidate`에 전달해 해당 게시판을 유지한다. 출처 없는 수동 일정은 없는 링크를 만들지 않는다.
- 캘린더에는 자동수집 중단과 정규 요일의 의미를, 상세에는 정규 요일 또는 기존 등록 당시 안내라는 차이와 변경 사항 자동 갱신 중단을 명시한다. 시간 입력/전용 행은 만들지 않으며 링크·이미지를 드래그하지 못하게 한다. 모든 날짜의 모든 카드는 계속 표시한다.
- 수집기는 소셜 전용 허용 출처를 제외하고, 혼합 출처에서는 소셜/휴무 후보를 문서 완료 키 생성 전에 제외한다. 소셜 AI 및 휴무 추출, 당일 보충 실행은 중단한다. 저장 직전과 서버 intake/자동등록에서도 같은 정책을 적용해 잔여/구형 실행을 차단한다. 강습/행사와 관리자 수동 등록 경로는 유지한다.
- 기존 정규 요일 생성/삭제 보호와 저장 원장은 수정하지 않는다. 지도 SDK의 전역 객체만 준비된 상태에서 `maps.load`를 호출하면 상세 전체가 실패한 인접 오류는 기존 준비 확인 조건을 `maps.load`까지 확장했다(`3d33d060`의 SDK 없음 방어 목적 유지).

## 검증과 운영

공개 API와 실제 공식 링크를 읽는 로컬 미리보기를 사용했다. 테스트용 DB 쓰기, 가짜 공개 일정, 전역 브라우저 종료는 하지 않았다. 프런트 빌드 및 회귀/반응형 결과는 ISSUE_LOG에 기록한다. UI 이외의 DB 스키마, 정규 생성 로직과 API 일정 데이터는 바꾸지 않아 DB 마이그레이션·전체 재수집은 제외한다.

Mini PC 백업 `~/ingestion-runs/social-links-20260925/`. 정상 wrapper 실행 `20260925_185154_3155615`는 exit 0, 보충 수집 브라우저/AI/자동등록 0. 이전 진행 파일은 초기화하지 않았다. 기존 6개 timer와 키오스크를 유지했다.

서버 백업 `/opt/swingenjoy/backups/social-links-20260925/`. 운영 SHA를 비교한 뒤 정책과 intake/자동등록 차단만 적용했다. 최초 health 확인 경로를 `/api/health`로 잘못 사용해 자동 원복됐으며, 실제 `/__health` 경로로 재적용·200 확인했다. 다른 로컬 미배포 서버 변경은 포함하지 않았다. `function-api.js` SHA `1914646803b6abe5a039db43ad89e8146eec2a21c065751b7875a2708ed9ff45`, 레지스트리 SHA `ed719ee9d7d67e26ee79aaa218d04ee236c3ba21185f89f239a4906c17790edd`.

롤백은 운영 모듈 백업과 해당 UI 변경으로 가능하다. 정책을 복원할 때는 UI 안내도 함께 맞춘다. 진행 원장과 이미 등록된 일정은 과거 백업으로 덮어쓰지 않는다. 소셜 자동수집 재활성화는 사용자 결정이 필요하다.
