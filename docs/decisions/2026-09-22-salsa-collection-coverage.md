# 살사 원문 수집과 예약 실행의 소유 범위

- 날짜: 2026-09-22
- 상태: 로컬 수집 코드·예약 설정 적용, 사용자 후속 지시에 따른 관리자 검수·공개 등록 61건 완료. 첫 예약 시각 실행은 아직 미검증.
- 요청: 정체된 살사 수집을 실제 씬 조사에 기반해 확대한다.

## 근거와 기존 구현 판정

**일부 있음.** 9/11에 보니따/DSN 후보를 단발 등록했지만 카카오/Meetup 원문 읽기는 실행기에 연결되지 않았다. 기존 공통 native 실행기는 확장 프로필·카페/Instagram·검증/등록을 이미 제공한다. 별도 `expanded-genre-native`의 제한된 웹 수집기를 늘리는 대신 실제 운영 중인 공통 실행기에 빠진 원문 해석을 연결한다.

실제 씬은 장소 운영자의 주간 소셜, 동호회/카페의 모집, 강사의 복수 지역 회차별 수업, 페스티벌 주최자 원문으로 나뉜다. 허브와 디렉터리는 원문 발견에 사용한다. [조사 기록](../salsa-collection-expansion-2026-09-22.md)에 원문 링크와 확인 수준을 구분했다. 경로 추가를 미래 일정 확보 또는 공개 등록 실적으로 세지 않는다.

## 결정

1. `public-schedule-sources.mjs`는 공개 DOM의 날짜별 원문 해석만 소유한다. 후보 ID·URL 정규화·장르/활동/장소/DJ 검증·저장·공개 등록은 기존 `candidate-utils`와 공통 native/서버 API의 책임을 유지한다. 새 테이블·큐·상태값·등록 API는 만들지 않는다.
2. Meetup은 실제 예정 카드의 회차 날짜/장소를 사용한다. 본문의 반복 문구나 최초 시작일로 날짜를 생성하지 않는다. 강습 시간표는 해당 요일만 읽고 다른 요일 장소나 부속 소셜을 별도 행사로 늘리지 않는다. 카카오는 게시 연도·일자·요일·홀별 프로그램을 확인한다.
3. 공식 Instagram 15개와 JDC Meetup을 추가하되 신규 출처는 기존 수동 검수 정책을 유지한다. 기존 보니따/DSN 소셜은 기존 자동 검증을 거친다. AI 거절, 다른 홀 DJ, 로그인 장벽을 출처별 예외로 우회하지 않는다. 엄격 중복·동일 장소/날짜 충돌·관리자 삭제 보호와 시간 전용 UI 금지는 그대로다.
4. 기존 Mac 래퍼를 호출하는 살사 전용 launchd 두 설정을 둔다. 공개 원문/카페 7개는 매일 12:10·18:10, Instagram 17개는 14:10에 실행한다. 프로필은 `expanded-ingestion`, 범위는 `salsa`로 고정한다. 기본/기존 스윙 일정은 유지하고 다른 확장 장르는 수동 실행을 유지한다. 기존 20분 예산·공유 실행 잠금을 사용하며 Telegram 발송은 비활성이다.
5. 진행 상태 구조는 기존 것을 사용하고 프로필/장르별 파일명으로 스윙 상태 충돌을 막는다. 기존 스윙 같은 날 복구 전용 실행 조건은 살사에 적용하지 않는다. 일정은 Mac 실행 환경이 유지되어야 동작하며 잠금 점유·로그인 제한·실행 예산으로 다음 실행에 남는 출처가 있을 수 있다.

## 검증·영향·복구

- 실제 신규 저장 48건(강습 45, 소셜 3), 기존 DSN 중복 제외 8건, 저장 실패 0건. 읽기 전용 원장과 공개 API를 비교해 신규 공개 0건 및 기존 살사 8건 전체 레코드 동일을 확인했다. AI 활동/DJ 근거 검토와 신규 출처 수동 정책에 따른 보류를 그대로 유지했다.
- 표준 검사와 등록 연결 48개·충돌 8개·AI 검증 38개 회귀 통과. 소스 DOM 실독, 날짜·요일·연도·홀·활동 분리·언어 URL 정규화·진행 상태 분리를 검증했다. launchd 두 설정은 설치/등록 확인 완료이나 첫 예약 실행은 아직 도래하지 않았다. 화면·서버·스키마 변경이 없어 UI 전체 검사·빌드·배포·마이그레이션은 제외했다.
- 새 구조는 원문 해석 어댑터와 기존 래퍼 설정뿐이며 후보/등록 책임의 중복은 없다. 기존 source ID와 레거시 스윙 진행 파일명을 보존한다. 데이터 마이그레이션은 없다.
- 복구 시 `com.rhythmjoy.codex-ingestion-salsa-public`, `com.rhythmjoy.codex-ingestion-salsa-regional` 두 launchd 작업을 해제하고 이번 코드/레지스트리 변경만 되돌린다. 기존 스윙 작업이나 진행 파일을 삭제하지 않는다. 저장 후보는 기존 원장에서 검토하며 다른 후보/공개 이벤트를 일괄 삭제하지 않는다.

## 같은 날 후속 검수

사용자가 강습 등록과 소셜 추가 검증을 명시했다. 자동 승인 조건을 변경하지 않고 기존 관리자 수동 경로로 61건을 공개했다. 홍턴·바바루 공식 원문을 레지스트리에 추가하여 실제 Instagram 예약 선택은 19개다. 기존 DOM 정렬의 아이콘 고정 표시 판독을 보완했고 월간 고정 글 보존·예산·작성자 검증은 유지했다. [후속 결과](../salsa-social-followup-2026-09-22.md)의 최종 수치가 위 최초 저장 검증보다 나중 상태다.


## 2026-09-23 보완: 에버라틴과 장소 원장

에버라틴 레벨별 강습 6개와 공식 Instagram을 기존 레지스트리에 연결한다(공개 13개, Instagram 20개). 동호회와 같은 장소 운영자 원문을 대조하며 출처별로 행사를 복제하지 않는다. 기존 AI 원본 소셜 추출은 스윙과 살사에 적용하되 살사는 회차별 근거에 살사 장르가 명시돼야 한다. 바차타/키좀바 단독 근거는 제외한다. 원본 슬라이드 판독은 최대 8회/10초, AI 입력은 기존 3장 상한을 유지해 나눠 처리한다. 원문 이탈·접근 차단·미완료는 완료로 숨기지 않는다. 자동 공개 정책은 승격하지 않으며 기존 검수·충돌·DB 소유권을 유지한다. 적용된 원문/보호 목적/실제 등록과 자동 브라우저의 남은 한계는 [9/23 조사 기록](../everlatin-ingestion-audit-2026-09-23.md)에 남긴다.


## 2026-09-23 후속: 수정형 강습 공지의 근거 범위

- 강습 전용 원문에서 제목이 강습을 명시하고, 하나의 독립된 `강습공지/수업안내` 구간에 실제 개강일이 있는 경우 그 원문 구간을 후보 근거로 사용한다. 제목 또는 강습 구간 자체에 MT가 있거나 경계가 불명확하면 기존 제외를 유지한다. 키워드 자체를 지우거나 출처별 면제를 만들지 않는다.
- 명시적인 요일반 제목과 각자의 `N월 N일부터/개강/시작`이 둘 이상 확인될 때만 반을 분리한다. 중복·교차 수강 등 공통 안내는 보존하고 각 반 내부에서는 기존 첫 날짜만 사용하는 규칙을 유지한다. 한 강습의 2·3주차 날짜를 새 강습으로 만들지 않는다.
- 연도는 계속 최초 작성일 전후 1년 안에서만 정한다. 수정형 강습의 `화요반 9월 15일부터` 같은 정확한 반/개강 문맥이 있으면 그 요일과 일치하는 유일한 해를 사용한다. 일반 소셜의 요일만으로 연도를 당기는 방식은 기존 회귀검사에서 거절했으며 적용하지 않는다. 수집 시점의 연도로 과거 글을 재활용하지 않는다.
- 공개 목록의 공지 숨기기는 해제하고 댓글 이동 링크는 정규화 전에 제외한다. 기존 DOM 판독기를 테스트 가능한 위치로 이동했으며 등록 책임과 스키마를 추가하지 않는다. 원문에 쓰인 ‘강남역 라틴바’는 검증된 기존 장소 ‘클럽 라틴’으로 공통 수집기 장소 별칭에 연결한다.
- Instagram 로그인/가입 대화상자는 원본 이미지가 배경에 있더라도 접근 실패다. 불완전 원문을 AI에 보내지 않고 기존 접근 불가·미완료 원장으로 남긴다. 자동 프로필의 로그인 복구는 여전히 필요하다.

복구는 이 근거 판독·목록/별칭 변경만 되돌리면 된다. 데이터 마이그레이션이나 공개 이벤트 삭제가 필요하지 않다. 변경은 설치된 로컬 예약 작업이 다음 실행부터 읽는 작업 트리에 적용되며 서버 배포와 별개다.
