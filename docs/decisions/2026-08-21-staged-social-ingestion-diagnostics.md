# 단계별 소셜 수집 진단과 결정론 등록 경계

- 날짜: 2026-08-21
- 상태: 채택·구현
- 대체 범위: `2026-08-14-grounded-ai-social-ingestion.md`의 모든 소셜 자동등록 후보에 2차 AI 승인을 필수로 요구하는 결정 중, 공식 원문의 완결된 날짜별 소셜 구간

## 배경

수집 실행은 공식 링크 탐색, 원문 해석, 날짜별 후보 분해, Cafe24 후보 저장, 자동등록을 차례로 수행하지만 결과 요약은 신규·스킵·자동등록 합계만 보여 줬다. 원문 링크가 틀린 것인지, 활동 분류가 실패한 것인지, AI 검증이 멈춘 것인지, 서버 등록 정책이 차단한 것인지 운영자가 구분하기 어려웠다. 2026-08-21 해피홀 원문은 후보까지 저장됐지만 AI 사용량 제한에서 자동등록이 멈췄고, 스윙타운 월간 원문은 날짜·DJ 분해에 성공했지만 해당 게시판이 수동 전용으로 설정돼 자동등록되지 않았다.

## 기존 구현 판정

- 판정: 일부 있음
- 재사용: `getAutomationSourceList('swing-daily')`, 소스별 링크 탐색, `prepareCandidate()`·`buildCafe24Payload()`, 결정론 후보 ID, `scraped_events` 후보 원장, 자동등록 서버 재검증, Instagram 진행 체크포인트
- 정확한 빈틈: 단계별 성공·실패 수치와 차단 사유가 없었고, 2026-08-15 변경에서 이미 있던 `date_scoped_social` 결정론 경로가 AI 필수 경로로 다시 연결됐다. 스윙타운 월간 게시판은 공식 원문임에도 모든 활동을 수동으로 묶어 날짜별 정규 소셜까지 자동등록하지 못했다.

## 결정

1. 새 테이블·큐·상태값은 만들지 않는다. 후보 원장은 `scraped_events`, 중단 재개는 기존 진행 체크포인트가 계속 소유한다. 원문을 하나 더 저장하는 병렬 원장은 중복 소유권과 보존 정책을 새로 만들기 때문에 이번 변경 범위에서 제외한다.
2. 실행 결과에 `discovery`, `classification`, `decomposition`, `persistence`, `registration` 단계별 건수와 최대 40개의 구조화된 차단 사유를 기록한다. Telegram 요약에도 단계별 수치와 대표 차단 사유를 출력한다.
3. 공식 수집원에서 한 후보의 저장 원문에 정확한 날짜, 소셜 표지, 전체 DJ와 검증된 장소가 함께 있는 `date_scoped_social`은 AI 서비스 가용성에 의존하지 않는다. 수집기 규칙을 통과한 뒤 서버가 저장 원문을 다시 읽어 같은 네 필드를 독립 검증해야만 등록한다.
4. 비정형 다중 이미지, DJ 미공지, 날짜·DJ 대응 불완전, 검색 발견, 혜택, 강습·행사는 기존 AI·이미지·수동 검수 경계를 유지한다.
5. 스윙타운 월간 게시판은 날짜별 DJ가 완결된 정규 소셜만 shadow 자동등록에 참여한다. `졸업파티`, `졸공`, 행사·대회 표지가 있는 구간은 소셜 자동등록 준비 단계에서 차단하고 후보로만 남긴다.
6. `DJ는 사보이지기 ★테일★님`처럼 역할명 뒤에 장식된 활동명이 있는 표현은 역할명이 아니라 장식 안의 실제 활동명을 DJ로 사용한다.

## 운영·회귀 경계

- 같은 원문·날짜의 결정론 ID와 서버 중복 검사는 유지한다.
- 생성 정규 소셜은 실제 후보가 등록된 뒤에만 대체한다.
- 날짜, 장소, DJ, 소셜 표지 중 하나라도 저장 원문에 없으면 결정론 경로를 닫는다.
- 졸업파티 같은 특수 행사를 일반 소셜로 자동등록하지 않는다.
- 단계 진단은 실행 결과와 로그만 확장하며 운영 DB 스키마를 변경하지 않는다.
