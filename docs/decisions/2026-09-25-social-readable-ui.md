# 소셜 화면 가독성과 공식 공지 동작

- 날짜: 2026-09-25
- 상태: `56a85735` 커밋·푸시 후 프런트 공개 배포 완료. 공개 version `1790336697731`, 320/390/1440px 검증 통과.

사용자는 앞선 공식 공지 안내가 문구 추가에 그치고 여전히 읽기 어렵다고 지적했다. 자동수집 복구 정책은 유지하면서 실제 화면 배치를 수정한다.

증상 → 판정 → 표시 → 결과: 길어진 장소/DJ → `getCalendarSocialFitFontSize`가 고정 48px 너비에 맞춰 최소 4.8px까지 축소 → 높이 28px의 두 줄 카드와 긴 안내 상자 → 장소·상태·링크를 알아보기 어려움. 기존 구현은 **일부 있음**. `calendarLayoutMetrics`, 날짜 셀, 상태/출처 유틸리티와 상세의 날짜·장소·링크를 재사용한다. `6be6fa60`/`37932ebc`의 짧은 카드 안에 정보를 맞추던 목적은 확인했으나 글씨 축소는 읽기와 양립하지 않았다. 회차 판정·출처 URL·저장 데이터는 바꾸지 않는다.

달력에서 자동 글씨 축소를 제거한다. 장소 11.5px·상태 11px을 유지하고 줄바꿈과 최소 64px의 자동 높이로 내용을 담는다. 길이가 더 길면 카드 자체가 늘어나며 모든 일정은 날짜 셀에 계속 표시한다. 기존 높이 계산의 사회 일정 상수도 함께 맞춘다. 등록 일정·정규 요일·휴무는 글자와 색을 함께 사용한다. 안내는 소셜/자동수집 제목, 공식 공지 연결 동작, 표시 범례로 나눈다.

상세에서는 일정 상태와 큰 제목·포스터, 날짜·장소를 먼저 보여준다. 공식 출처는 18px 제목의 큰 파란 버튼, 개별 원문은 독립된 두 번째 버튼이다. 긴 공지 본문은 기본적으로 접되 모두 펼쳐 읽을 수 있다. 근거의 내부 표식 `[AI_POSTER_TRANSCRIPTION]`만 공개 표시에서 ‘포스터 안내’로 바꾸고 저장값/관리자 편집은 보존한다. 포스터가 없는 화면의 빈 이미지 칸은 숨긴다. 시간 전용 정보, 새로운 수집 상태나 DB 필드는 없다. 링크·카드·이미지는 비드래그다.

실제 공개 API를 읽는 390/320/1440px Chromium에서 카드 75개·글자 최소 크기·내용 잘림 0·날짜가 공식 링크 위에 있는지·두 링크 목적지·본문 펼치기·가로 넘침 0·pageerror 0을 검사했다. 기존 달력 분류/휴무/기본 회차/원문 분리·행 정렬 검사도 유지했다. 데이터 판정·수집기를 다시 수정하지 않아 이 UI 때문에 운영 원장을 재작성하거나 수집을 강제 실행하지 않는다.

## 배포 경계

기존 배포는 전체 앱/API 또는 통계 모듈만 지원한다(**일부 있음**). 이번 UI에 이미 반영된 서버 수정/별도 운영 수집기를 다시 덮어쓸 필요가 없어, 기존 `scripts/deploy-cafe24.sh`에 `--frontend-only`를 연결한다. 같은 소유자의 깨끗한 소스·main 포함·선푸시 검증, 자산 전송, health 확인, index/service-worker/version 순서의 공개를 재사용하며 새 배포기를 만들지 않는다. 이 모드에서는 API·DB 마이그레이션·패키지·cron 변경과 서버 재시작을 수행하지 않는다. 실제 script를 외부 명령 기록기로 실행해 범위 분리·기존 전체 경로·더러운 소스 거부를 확인한다.

운영에 이미 배포된 `161a8e17` 화면 기반과 `ff156bb7` 통계 이력을 통합한 깨끗한 별도 작업본에서 관련 변경만 커밋·푸시한 후 배포한다. 원래 작업 폴더의 다른 미완료 실험실/키오스크 변경은 보존한다. 기존 운영 entry 세 파일은 별도 사본으로 보존하고 이전 해시 자산은 삭제하지 않는다. 롤백은 저장된 entry 사본을 복원하며 서버·DB·수집 진행 파일은 바꾸지 않는다. 배포 결과는 ISSUE_LOG에 기록한다.
