# 무료·할인 이벤트 메인 배지의 확인 상태 경계

- 날짜: 2026-08-21
- 상태: 승인, 구현 완료, 메뉴 고정 원장 연결 보완

## 배경

메인 화면에는 무료·할인 이벤트 목록으로 이동하는 바로가기가 있고, 목록은 일반 일정과 상시 원데이 모집 링크에서 `benefit_eligible=true`인 항목을 합쳐 표시한다. 새 요구사항은 이 데이터의 원본이나 알림 전달 상태를 바꾸지 않고, 사용자가 아직 목록에서 확인하지 않은 현재 혜택 수만 바로가기에 보여주는 것이다.

자유게시판은 로그인 사용자의 게시글 단위 읽음을 서버에 저장하지만, 혜택 목록에는 계정 간·기기 간 동기화를 요구하는 기존 읽음 도메인이나 소유 테이블이 없다. `user_notifications`를 재사용하면 종 모양 알림함의 읽음 의미와 충돌한다.

## 결정

1. 배지 대상은 `benefit_eligible=true`이면서 오늘 기준 종료되지 않은 일정과 활성 상시 원데이 혜택의 고유 ID다. 일반 일정과 종료된 혜택은 제외한다.
2. 혜택 목록과 메인 배지는 같은 날짜 판정 함수와 상시 원데이 변환·조회 함수를 사용한다. 같은 책임의 별도 분류기나 데이터 소유자를 만들지 않는다.
3. 확인 상태는 브라우저 `localStorage`의 `swingenjoy:benefit-events-seen:v1`에 ID 집합으로 저장한다. 로그인 상태는 `user:<id>`, 비로그인 상태는 `guest` 범위로 분리하고 범위당 최근 5,000개만 보존한다.
4. 메인에 고정된 혜택 메뉴 아이콘을 누를 때 현재 항목을 즉시 확인 처리하고, `/benefit-events`에 직접 진입한 경우에도 데이터 로드가 성공하면 같은 처리를 수행한다. 같은 탭은 사용자 이벤트, 다른 탭은 저장소 이벤트로 배지 상태를 갱신한다.
5. 최초 확인 기록이 없는 브라우저에서는 현재 혜택 전체를 새 항목으로 표시한다. 이후 새 고유 ID가 추가되면 그 수만 다시 표시한다.
6. 이 상태는 사이트 알림이 아니므로 `user_notifications`의 `is_read`, 푸시 전달 상태, 일정·원데이 원본 레코드를 수정하지 않는다. 다른 기기 간 확인 상태 동기화는 현재 요구 범위에서 제외한다.
7. 메인 혜택 진입점의 노출 소유자는 `HomeV2MenuPanel`의 기존 고정/순서 원장이다. `benefits`가 고정된 최대 5개에 포함된 경우에만 메인 아이콘과 배지를 노출하며, 강제 추가나 광고 영역의 독립 바로가기를 두지 않는다.

## 결과와 롤백

- 새 DB 테이블·상태값·마이그레이션 없이 메인 배지의 단일 목적만 추가한다.
- 혜택을 고정하지 않은 사용자에게는 확장 메뉴에서만 혜택 진입점을 보이고, 메인 광고 영역에는 별도 예외를 만들지 않는다.
- 과거 혜택을 목록에 계속 보여주는 기존 동작은 유지하되 배지 계산에서는 제외한다.
- 롤백은 메인 배지 훅·표시 연결과 해당 로컬 저장 키 사용을 제거하면 되며, 서버 데이터 복구는 필요하지 않다.
