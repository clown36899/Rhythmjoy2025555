# 지정 강습 게시판의 자동수집 복구와 기존 일정 보호

날짜: 2026-10-12 KST. 상태: 구현·로컬/운영 등록 경로 검증 및 후보 정리 완료. 기존 역방향 SSH로 정규 예약 장비 접속·코드 대조 완료, 반영 검증 진행 중. 프런트엔드 공개 배포는 하지 않았다.

## 기존 책임과 조사 경계

사용자가 확인한 강습 원장은 스윙타운 외강&행사&연습실 게시판 `https://cafe.naver.com/f-e/cafes/10342583/menus/13?viewType=L`이다. `swingtown-lessons-cafe`는 이미 `swing-daily`의 class-only·explicit venue·shadow 자동등록 대상으로 등록되어 있다. 새 출처, 검색어, 수집 프로필, 예약, 큐, DB 필드를 만들지 않는다. 기존 소스 레지스트리를 바꾸지 않고 해당 고정 게시판만 실제 수집·복구했다.

기존 구현은 **일부 있음**이다. registry → native Naver reader/날짜·장소/분류 → AI 재검증 → 후보 저장 API → 공통 등록 핸들러/이벤트 변경 잠금 → events/후보 연결/알림 큐의 직접 호출부·테스트·기록과 해당 git 이력을 조사했다. 기존 `d61966c87`의 시간 오인 방지, `133257c26`의 명시 장소 보호, `fe2b77c68`의 원문·DJ 날짜 분리, `2d4e23c38`의 다중 일정 AI 보류, `7aab99d6e`에 남은 본문/선택·등록 충돌 보호를 확인했다. 이전 성공 원문 156739와 그 공개 일정, 신규 156849 등의 실제 본문·이동 후 frame을 대조했다.

## 원인과 공통 수정

- 외부 페이지 이동 완료 직후 `cafe_main`이 아직 붙지 않으면 바깥 mainFrame을 고정해 본문 준비를 기다리다 실패한다. 기존 reader를 쓰는 준비 함수가 실제 본문이 준비된 frame을 선택한다. 댓글·작성자·광고 frame은 본문으로 인정하지 않는다.
- class-only 스윙 게시판에서 카페 전체 고정 공지와 지난 강습 제목이 최신 외강 앞에서 검사 한도를 차지했다. 실제 board-notice 여부를 읽어 일반 최신 글을 먼저 본다. 기존 살사 신청 게시판의 개강 공지 우선순위는 유지한다.
- 날짜 주변 문자열의 고정 10번째 위치를 검사해 `10/26` 등의 두 자리 월을 시간으로 오인했다. 해당 날짜 토큰의 실제 앞/뒤만 검사한다. 날짜 옆 설명의 시각 때문에 날짜를 버리지 않는다. 점으로 쓴 시각·입금 마감·과거 첫 수업은 계속 제외한다. 기간의 다음 월을 이전 월의 추가 일자로 읽지 않는다.
- modern article_viewer의 FormNoticeContent가 원문에 섞여 기존 chrome 제거기가 첫 날짜 이전의 장소와 소개를 버렸다. 기존 original editor body를 좁혀 읽고 원본 이미지 소유권을 유지한다. 명시 장소 라벨의 기호·줄바꿈만 지원하며 지역·카페 소재지로 장소를 추정하지 않는다.
- 명시 강습 제목의 본문에 소셜이 언급되면 소셜로 분류했다. class-only 소스의 기존 강습 제목 판정을 먼저 쓰되 강사 모집·졸공과 실제 소셜을 강습으로 만들지 않는다.
- AI의 단일 날짜 문구가 한 강습 과정의 여러 수업일도 서로 다른 행사로 보류했다. 한 과정은 오늘 이후 첫 수업일 한 건만 허용한다. 이미 시작한 과정의 다음 수업을 신규 개강으로 만들지 않고, 독립된 과정/레벨/장소가 섞이면 검토한다. 기존 특강 분류와 AI/서버의 명시 class 근거 단어도 연결했다. 실제 AI 승인·98% 기준·원문 인용·날짜/장소/활동 재검증을 유지한다.

## 중복·검토·알림

기존 확정 중복 비교는 유지한다. 같은 날짜·장소에 같은 활동의 강습/행사도 있으면 기존 social 충돌 matcher를 공통 소유자로 확장해 **pending 검토**로 보류한다. 다른 DJ/강사라는 추정만으로 새 일정이라고 확정하지 않는다. 카페 URL과 신청서 URL이 다른 경우에도 실제 원문 안 신청·원문 링크와 기존 link1~3을 대조하고, 불확실하면 기존 사유 필드에 대상 ID를 남긴다. 날짜·장소가 같다는 이유로 공개 일정을 합치거나 삭제하지 않는다.

자동 요청은 원장에 연결되지 않은 회원의 기존 일정을 덮어쓰지 않는다. 자기 원장에 연결된 동일 일정 정정, 생성된 정규 소셜 교체, 관리자 검수 수동 등록, 관리자 삭제/휴무 보호는 유지한다. 저장 직전 기존 이벤트 변경 잠금 안에서 충돌을 다시 확인한다. 기존 social 함수 이름은 같은 matcher의 호환 export로 남긴다. 중복 사전 검증은 후보 상태를 쓰지 않는다.

`automatic` 등록의 이미 인증된 운영 요청에만 이번 점검용 `suppressNotifications: true`를 전달한다. 네이티브는 기존 실행 환경 설정으로 이를 전달할 수 있다. 새 알림 큐/DB 상태를 만들지 않고 기존 큐 생성 호출만 생략한다. 기본 등록 알림은 유지하며 텔레그램 테스트도 전송하지 않는다.

## 실제 반영과 확인

원문을 다시 읽고 실제 AI 0.99 승인 및 공통 등록 검증을 통과한 다음 세 강습을 운영 DB에 반영했다. 배포 중인 파일은 교체하지 않고 운영 의존성의 검증된 등록 핸들러 격리본으로 `automatic: true` 경로를 실행했다. 게시판 후보 저장은 기존 HTTP API를 사용했다. 서비스 배포로 테스트를 대신하지 않았다.

견우·뽈 10/12 강습은 회원의 기존 일정 `c9ccda22-b592-4fc6-8176-ca6fb1a74198`과 신청서가 같다. 원문 장소는 지역명 신촌뿐이므로 AI도 review를 반환했다. 후보 `4c2a71e0158f10d8`는 기존 일정 ID와 검토 사유를 남겼고 회원 일정의 전체 값은 유지했다. 과거 첫 수업을 지난 9월 강습 및 10/8 개강반은 이번 신규 등록에 포함하지 않았다.

과거 대기 후보 79건을 기존 제외 원장으로 전환하고 등록 완료/기존 공개 일정을 보존했다. 원본 백업은 운영 `backups/data-fixes/lesson-review-20261012-1791781102082.json`(0600), 추가 검토 백업도 같은 제한 접근 디렉터리에 있다. 후보 삭제·이미지 삭제 대신 기존 제외 상태를 사용해 복구 가능하게 남겼다. 미래의 검토 필요 후보를 무조건 삭제하지 않았다.

관련 UI/수집/AI/등록·완료·잠금·레거시의 고유 회귀 185건, 수집 표준, 대상 lint 오류 0·프런트/서버 빌드 및 공백 검사 통과. 모바일 390px·PC 1440px에서 운영 DB 읽기를 연결한 장르 선택·저장·재열기를 확인했고 화면 오류/가로 넘침은 0이다. 인증 응답은 브라우저 검증에서만 모의하고 쓰기는 차단했다. 모델 검증은 실제 원문을 사용했다. 한 AI 모의 CLI 검사가 병렬 부하로 5초 제한에 걸려 해당 파일만 단일 worker·10초 검사 제한으로 재확인했다.

소스 확대, 예약 추가, DB 마이그레이션, 실제 회원 세션 사용, 수집기 전체 출처 스캔과 무관한 사이트 전체 회귀는 변경 경계 밖이라 제외한다. 미니PC `kiosk-host.local`은 이름 조회 실패, 기록된 `172.30.1.14`는 SSH 연결 시간 초과다. 운영 서버 SSH는 정상이며 미니PC 예약 서비스·현재 실행 코드/진행 파일을 읽지 못했다. 이를 인증 실패나 자동 실행 중단으로 단정하지 않는다. 정규 예약 복구 완료라고 주장하지 않고 기존 운영 절차에 따른 실행 장비 반영을 남긴다.

## 실행 장비 접속 복구

mDNS와 기록된 사설 IP는 연결되지 않았으나 운영 서버 loopback 22013의 기존 역방향 SSH는 동작했다. 기존 kiosk-host.local 호스트 키를 검증한 ProxyCommand로 접속했다. 추가 터널·인증·서비스를 만들지 않았다. 6타이머 활성과 작업 0, kiosk-chrome/kiosk-display PID 1147499/1145182를 기준으로 보존한다. 설치된 4모듈은 독립된 혜택·DJ·Instagram 수정도 포함하므로 로컬 파일 전체로 덮지 않고 이번 Git 차이만 적용한다. 기존 소스 registry·설정·진행 원장·의존성은 유지한다.

실제 정규 전체 탐색 기록 `20261012_130000_1886775`에서 지정 게시판의 기존 완료 글 156798 skip 뒤 원문 frame 8000ms timeout을 확인했다. 15:00 중간 예약의 빈 same-day scan은 강습 전체 탐색의 성공 증거로 취급하지 않는다.
