# 살사 소셜의 기존 서버 자동등록 경로 사용

- 날짜: 2026-09-11
- 상태: 구현·검증·배포 및 대상 13건 서버 등록 완료 (79d7ba0d)

사용자는 수집한 살사 13건을 캘린더까지 등록하도록 요청했고, 스윙 서버 자동등록처럼 Mac 없이 처리해야 한다고 지적했다. 관리자 UI만 사용할 수 있다고 안내한 판단을 철회한다.

기존 출처 레지스트리의 등록 정책과 서버 `AUTOMATIC_REGISTRATION_SOURCE_RULES`에 공식 보니따 카카오/DSN Meetup의 social 활동만 연결한다. 보니따는 검증된 고정 장소를 사용하고 DSN은 회차별 원문/포스터의 명시 장소를 요구한다. 새로운 인증 수단·API·원장·큐를 추가하지 않는다. 기존 서버 API가 후보 재검증, 이벤트 이미지 보존, 중복 방지, 알림 큐, 등록 이벤트 ID 연결을 계속 소유한다.

영문 월명 날짜는 기존 `evidenceExplicitlyContainsCandidateDate`에서 한국어/숫자 날짜와 같은 책임으로 검증한다. 명시된 연도가 다르거나 일자/월이 다른 경우 거부하고 시간 숫자를 날짜로 쓰지 않는다. 기존 스윙 정규 소셜과 강습 검증을 유지한다.

운영 복구는 후보 13건을 백업하고 동일 ID·원문·날짜로 기존 저장 API를 통해 등록 준비 판정을 갱신한 뒤 서버 등록 API를 호출한다. 실제 이벤트 ID가 확인된 후보만 완료로 인정한다. 다른 관리자 세션을 사용하거나 수집기 승인 결과를 임의로 true로 덮어쓰지 않는다. 검증된 날짜별 소셜은 기존 결정적 검증 경로를 사용하며 AI 검증 결과를 위조하지 않는다.

배포 전 실패하면 코드 변경을 되돌리면 된다. 운영 등록 후 되돌릴 필요가 있으면 저장한 대상 후보/이벤트 ID와 백업만 사용하며 다른 일정은 건드리지 않는다. 이번 작업은 새 출처의 주기적 탐색기를 활성화하는 작업과 분리한다. 스윙 자동 수집의 출처 목록과 읽기 실패 시 캘린더를 유지하는 기존 정책은 바뀌지 않는다.
