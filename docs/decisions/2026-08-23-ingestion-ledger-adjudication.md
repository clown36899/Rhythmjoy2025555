# 2026-08-23 수집 후보 원장 재판정과 종결 상태 저장

- 상태: 채택
- 범위: `scraped_events` 저장 경로와 관리자 수집함 분류

## 배경

수집기는 원문 URL·날짜의 결정론 ID로 후보를 만들지만, 이미 pending인 같은 ID가 다시 들어오면 내용을 갱신하고 즉시 종료했다. 운영 이벤트 중복 판정은 신규 후보에만 실행돼, 후보가 먼저 수집되고 일정이 나중에 등록된 경우에도 관리자 신규 탭에 계속 남았다. 정책 탈락 후보와 같은 원문·제목의 다중 날짜 부수 후보는 저장하지 않고 건너뛰어 다음 실행에서 다시 처리될 수 있었다.

## 결정

1. 원문에서 만든 후보는 기존 `pending`, `collected`, `duplicate`, `excluded` 상태를 단일 원장으로 사용한다.
2. pending 후보는 같은 ID로 재수집될 때 운영 이벤트와 기존 후보 원장을 다시 판정한다.
3. 운영 일정과 고신뢰로 일치하면 기존 `duplicate`, 결정론 정책 또는 날짜 확장 규칙에서 탈락하면 기존 `excluded`로 종결한다. 제외 사유와 판정 단계는 후보의 구조화 메타데이터에 보존한다.
4. 중복 판정 우선순위는 운영 이벤트, 이전 후보 원장 순서다. 소셜은 날짜·장소·DJ가 모두 같아야 하며, 비소셜 본문 일치는 날짜·장소·활동과 12자 이상의 구체 제목이 모두 같아야 한다.
5. AI 오류만으로는 제외하지 않는다. 게시일·과거 날짜·게시판 탐색 영역처럼 결정론 근거가 있을 때만 종결한다.

## 유지하는 불변조건

- `collected`, `duplicate`, `excluded`는 일반 재수집으로 pending으로 되돌리지 않는다.
- 완전한 실제 공식 소셜이 `regular-social:` 생성본을 교체하는 기존 안전장치는 유지한다.
- DJ가 다른 소셜과 제목이 다른 강습은 같은 날짜·장소만으로 합치지 않는다.
- 운영 이벤트는 이 판정에서 삭제하지 않는다. 기존 원장 보정도 후보 상태만 복구 가능한 트랜잭션으로 바꾼다.
- 새 테이블·큐·상태값을 만들지 않는다.

## 결과와 롤백

관리자 신규 탭은 미판정 후보만 보여주고, 확인 가능한 중복은 중복 탭에 남으며 정책 탈락 후보는 원장에는 보존되지만 일반 탭에서 숨겨진다. 운영 보정 전 원본 JSON을 백업하므로 후보 상태와 메타데이터를 레코드 단위로 복원할 수 있다. 코드 롤백 시에도 기존 상태값만 사용하므로 스키마 롤백은 필요하지 않다.
