# 서버가 마감하고 저장하는 일별 방문자 통계

- 날짜: 2026-09-23
- 상태: 채택. 같은 날의 ‘첫 조회 후 캐시 저장’ 설계를 대체한다.

## 문제와 기존 책임

기존 모달은 원시 활동·세션 로그를 브라우저로 내려받아 계산했다. 첫 수정은 과거 기간을 조회한 후 site_usage_stats에 저장했기 때문에, 사용자가 요구한 ‘지난 날짜는 조회 전에 계산·저장되어 있어야 한다’는 조건을 만족하지 못했다. 캐시 읽기에도 ‘데이터 분석 중’이 표시되어 저장값 조회와 재계산을 구분할 수 없었다.

운영 DB에는 실제 조회 후 생성된 v1 보고서가 있었다. 기존 scripts/run-cafe24-cron-refresh-stats.mjs는 현재 빌드 허용 목록에서 제외된 cron-refresh-stats 함수를 호출했으며 일별 보고서를 마감하는 역할을 하지 않았다. 서버 getAnalyticsSummaryV2의 권위 집계·제외 기준, 관리자 전용 site_usage_stats, 기존 정기 실행 스크립트와 배포 명령은 재사용할 수 있다. 공개 metrics_cache에는 개인 상세를 저장하지 않는다.

## 최종 책임 분리

1. getAnalyticsSummaryV2는 기존 핵심 방문자·논리 세션 판정의 소유자로 유지한다. 내부 호출에 원본 묶음을 전달할 수 있도록 확장하고, 일별 입력에 전역 관리자 기기 제외와 회원 ID 정규화 결과를 담는다. 기존 report 플래그 없는 RPC 응답은 유지한다.
2. 모달의 상세 계산을 analytics-report-builder.ts로 이동한다. UI와 서버에 두 계산기를 남기지 않는다. 서버의 analytics-reports.ts가 조회·일별 마감·명시 재생성의 소유자다. 빌드 결과는 기존 dist-cafe24에 포함한다.
3. 기존 site_usage_stats에 analytics-report:v2:시작일:종료일 ID로 일별 summary/users/guests와 기간 결합에 필요한 inputs를 저장한다. 보고서/기간 입력은 gzip+base64로 압축하고 report_encoding으로 구분한다. 먼저 저장된 비압축 v2도 읽는다. 운영 MySQL의 max_allowed_packet은 1MiB이며 큰 보고서를 그대로 쓰면 실패하므로, 특정 날짜 예외나 DB 전역 설정 변경 대신 공통 저장 형식을 개선했다. 버전과 일별 범위를 키로 사용하고 v1·레거시 숫자 스냅샷은 수정하지 않는다. 회원 메타데이터는 해당 날짜에 관련된 ID/이메일 연결만 저장한다. 새 테이블·큐·서버 엔드포인트는 만들지 않는다.
4. 기존 통계 cron 실행 스크립트를 네이티브 마감 작업에 연결한다. 5분 간격으로 누락을 보충하며 저장된 날은 건너뛴다. 기존 30분 논리 세션 경계를 고려해 KST 00:35부터 전날을 마감한다. 중단 후에는 누락일만 재시도한다. 운영 방문 기록 전체 기간과 최근 1년의 0건 날짜도 최초 전환 때 채운다.
5. 과거 하루 조회는 DB의 일별 결과만 읽는다. 조회 요청이 원장 계산이나 backfill을 시작하지 않는다. 누락 시 pending으로 응답해 UI가 무한 로딩 대신 준비 상태와 다시 조회를 표시한다. 마감 스캔이 확인한 coverage보다 앞선 날짜의 0건과, 확인 범위 내 실제 누락은 구분한다.
6. 여러 날짜의 고유 방문자 수는 일별 인원 합계로 만들지 않는다. 저장된 일별 inputs를 결합해 기간 중복을 제거한다. 오늘이 포함되면 오늘의 최신 자료만 추가하며, 이미 마감된 과거 원장은 다시 읽어 결과를 바꾸지 않는다. 전역 관리자 기기 판정을 위해 오늘 계산의 서버 입력 로딩에는 전체 원장 참조가 남아 있지만 과거 일별 보고서를 재계산하지 않는다.
7. 원장 정정·늦은 유입·판정 규칙 변경 후 재생성은 관리자 명시 동작이다. 기존 create_usage_snapshot RPC에 report 경로를 연결해 읽기 RPC의 네트워크 재시도가 재생성을 반복하지 않게 한다. GET_LOCK으로 cron과 수동 재생성을 직렬화한다. 계산/조회 실패 시 기존 일별 결과를 덮지 않는다. 규칙 변경에는 보고서 버전을 올린다.
8. 브라우저는 보고서 읽기와 렌더만 한다. 원시 로그 조회·집계·자동 snapshot 쓰기를 제거했다. 일반 읽기는 30초 안에 실패 상태로 끝내고 이전 응답이 새 날짜 화면을 덮지 않도록 한다. 표시는 ‘통계 불러오는 중’으로 구분한다.

## 불변조건과 복구

KST 절대 시각 경계, 관리자·기기·내부·봇·데이터센터 제외, 회원/게스트 연결, 30분 논리 세션·체류 상한을 유지한다. session_start가 없는 레거시는 기존 서버의 created_at fallback으로 날짜를 정한다. 원본 로그·회원 원장·레거시 시간/스냅샷은 변경하지 않는다. 보고서는 파생 데이터이며 해당 날 명시 재생성 또는 버전 증가로 복구한다. 완성한 날만 단건 원자 upsert하고 전체 backfill이 성공한 뒤 coverage를 기록한다.

## 배포 경계

사용자가 지정한 ‘통계만 배포’를 유지한다. 기존 --analytics-only 경로에서 검증된 운영 프런트엔드 의존 모듈을 재사용한다. 서버 generic-data-api.js는 운영 파일의 해시를 확인하고 해당 브랜치의 통계 변경 부분만 적용한다. 운영의 다른 미커밋 기능을 HEAD 버전으로 교체하지 않는다. 새 서버 계산 묶음·기존 통계 실행 스크립트·통계 cron만 추가하고, 서버 헬스와 과거 backfill 완료 후 새 통계 화면을 공개한다. 기본 앱 buildTime을 유지하며 version.json의 analyticsReportCommit/Module/Version으로 확인한다. 이미 열린 탭은 새로고침 후 적용된다.

이전 index/version/API/계산 묶음/cron을 배포 스테이징 디렉터리에 보존한다. 실패하면 해당 파일을 복구하고 서비스를 재시작한다. 이미 저장된 정상 v2 보고서는 삭제하지 않는다. 전체 배포 경로도 같은 서버 빌드·정기 작업을 포함한다.

## 선택한 검증

과거 조회 무계산, 사용자 방문 없는 자동 마감, KST 마감 유예, 기존 날 건너뛰기·누락 복구, 0건, 여러 날의 동일 회원 중복 제거, 오늘+고정 과거 결합, 전역 관리자/봇 제외, 레거시 세션 날짜, 실패 시 기존 보고서 유지, cron/수동 잠금, 빈 날짜와 누락 구분, UI 읽기/명시 재생성/재시도/늦은 응답/시간 제한을 검증한다. 운영 9월 20·22일 원본의 새 계산은 기존 저장 보고서의 회원/게스트/활동/논리 세션·상세 목록 수와 일치했다. 수집·이벤트·게시판의 기능 변경이나 전체 원장 재작성은 범위에서 제외한다.
