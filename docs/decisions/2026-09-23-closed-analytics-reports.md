# 종료된 기간의 방문자 통계 재사용

- 날짜: 2026-09-23
- 상태: 채택

## 배경과 기존 책임

운영 통계 모달은 계산 결과를 메모리 Map에 쓰고 읽지 않았다. `site_usage_stats`는 관리자 전용 generic_records 저장소로, 기존에는 조회 시점의 일부 방문자 숫자를 저장했다. `metrics_cache`는 공개 조회가 가능하므로 회원·게스트 상세가 포함된 보고서의 저장소로 사용하지 않는다.

## 결정

- 기존 관리자 전용 `site_usage_stats`에 보고서 JSON을 저장한다. 새 테이블·큐·서버 API 없이 기존 id 조회/upsert를 재사용한다. `analytics-report:v1:시작일:종료일` ID와 `report_version`, `report`로 레거시 숫자 스냅샷을 구분한다. 저장 책임은 현재 전체 보고서를 만드는 SiteAnalyticsModal이며 공통 접근은 analyticsReportCache에 둔다.
- KST 기준 오늘보다 종료일이 앞선 유효 기간만 저장한다. 해당 기간을 종료 후 처음 조회할 때 계산·저장하고 이후 동일 기간은 저장된 summary/users/guests를 함께 표시한다. 조회가 시작할 때 오늘을 포함했다면 자정을 지나 완료해도 과거 보고서로 저장하지 않는다.
- 오늘 포함 기간과 전체 요약은 기존 집계 기준으로 최신 원장을 읽는다. 기간 고유 방문자를 일별 숫자의 합으로 대체하지 않는다. 이 변경은 오늘 포함 기간에서 과거 원장 읽기까지 없애는 증분 집계는 아니다.
- RPC·관리자 제외 기준·세션·설치·상세 조회 실패나 페이지 상한 도달 시 부분 결과를 확정 저장하지 않는다. 0명은 유효 결과로 저장한다. 저장 실패 시 계산 결과와 미저장 안내를 표시한다. 늦게 도착한 이전 요청은 현재 화면을 덮지 않는다.
- 원장 정정·지연 유입·관리자 식별 변경 후에는 기존 새로고침을 명확히 표시한 `다시 계산`으로 해당 기간을 갱신한다. 집계 규칙/데이터 계약 변경 시 보고서 버전을 올린다. 일자가 지났다는 이유만으로 원장이 영원히 불변이라고 가정하지 않는다.
- 기존 KST 경계·관리자/봇/내부/데이터센터 제외·회원/게스트 연결·논리 세션·레거시 필드는 유지한다. 일반 숫자 스냅샷은 오늘 하루 조회에서만 생성하며 종료된 기간 보고서의 snapshot_time은 해당 종료일이다.

## 배포 경계

사용자가 통계 개선만 배포하도록 지정했다. 운영 서버는 작업 폴더의 다른 미커밋 변경을 이미 포함하므로 깨끗한 HEAD 전체를 배포하면 이를 되돌릴 위험이 있다. 기존 deploy-cafe24.sh에 `--analytics-only`를 연결하고 깨끗한 커밋·main 포함·선행 푸시·서버 대상 검증을 그대로 적용한다.

이 경로는 확인한 운영 기본 빌드 1789750324455의 통계/주 모듈 해시를 확인하고 새 통계 모듈만 만든다. 운영 index에 import map을 삽입해 해당 모듈의 경로만 바꾸며 기존 CSS·React·API 클라이언트·필터 함수를 공유한다. 다른 번들·서버·DB 마이그레이션·서비스 워커는 업로드하지 않는다. 기본 빌드 ID를 유지하고 version.json의 analyticsReportCommit/analyticsReportModule로 부분 배포를 확인한다. 이미 열린 화면은 새로고침 후 적용된다. 기준 빌드가 바뀌면 부분 배포를 중단하고 의존 관계를 재검토한다. 이후 정상 전체 빌드는 같은 소스 변경을 포함하고 import map을 자연스럽게 대체한다.

## 복구와 검증

서버의 .deploy-analytics-커밋 디렉터리에 직전 index/version을 보관한다. 두 파일을 복원하면 모듈 전환이 취소된다. 보고서 행은 파생 데이터이며 기존 원장과 레거시 숫자 스냅샷은 변경하지 않는다. 보고서가 잘못되면 명시 재계산 또는 버전 증가로 복구한다.

검증은 과거/오늘·KST 자정·저장 없음/레거시·0명·명시 재계산·실패/재시도·상세 동시 복원·늦은 응답, 기존 순수성/세션 테스트와 운영 의존 모듈을 사용한 모바일 렌더링에 한정한다. 원본 집계 알고리즘과 다른 화면은 변경하지 않으므로 수집·소셜·게시판 전체 회귀나 운영 원장 재작성은 하지 않는다.
