# 2026-09-30 열람 권한에 따른 자유게시판 새 글 집계

## 원인과 기존 보호 목적

최근 비공개 글을 읽지 않은 관리자도 새 글 숫자가 0이었다. `listUnreadFreeBoardPosts`와 공용 `getFreeBoardUnreadActivity`가 읽음 원장을 대조하기 전에 모든 비공개 글을 제외했다. 7/26 `16b0abc0`의 비공개 포함 집계를 8/3 `3c0dae04`가 회원별 읽음 상태로 전환하며 제외했고, 9/19 `986642a9`의 인증·응답 경합 및 댓글 스냅샷 수정도 이 조건을 유지했다. 기존 보호 목적은 본인 글·이미 읽은 글의 재알림과 열람 불가능한 글의 노출 방지다.

같은 책임의 구현은 **일부 있음**이다. 상세 열람과 읽음 저장은 이미 `canViewHiddenBoardPost`로 작성자·관리자 권한 및 레거시 사용자 ID를 판정하고, 회원 API·공용 집계·화면 배지·읽음 원장이 모두 존재한다. 누락은 집계가 기존 열람 권한 판정을 사용하지 않는 연결이다.

## 결정과 불변조건

- 회원 API가 기존 `canViewHiddenBoardPost`를 집계 전 필터와 공용 집계에 전달한다. 별도 관리자 판정이나 특정 글·사용자 예외를 만들지 않는다.
- 기존 공용 함수의 마지막 선택 인수로 열람 판정을 받는다. 인수를 생략하는 비로그인 화면은 기존처럼 공개 글만 센다. 새 함수·필드·테이블·큐·API·저장 책임은 추가하지 않는다.
- 본인 글·댓글 제외, 14일 기간, 상세를 실제 열었을 때만 읽음 저장, 사용자별 읽음 상태, 댓글 ID 스냅샷의 합집합 및 레거시 시각 기준, 숨겨진 댓글 제외를 보존한다. 읽을 수 있는 비공개 부모의 새 공개 댓글도 같은 규칙을 따른다.
- 비공개 원문이나 공개 목록의 가림 처리는 변경하지 않는다. 권한 없는 회원은 비공개 글·댓글을 집계하지 않고 비로그인 회원 API는 401이다.
- 이 결정은 [8/3 계약](2026-08-03-notification-delivery-contract.md)의 6번 중 비공개 글 일괄 제외만 갱신한다. 알림함·Web Push 전달·발송 정책과 독립적이다.

## 검증과 배포

기존 테스트에 관리자 미읽음 비공개 글(레거시 참 값 포함), 읽은 뒤 제거, 관리자/레거시 작성자의 비공개 부모 댓글, 비권한 회원·비로그인 제외를 확장했다. 수정 전 6개 실패로 재현했고 수정 후 기존/인접 5파일 48개와 배포 검사 6개가 통과했다. 홈 숫자 1과 목록 NEW의 읽음 후 제거도 기존 컴포넌트 검사에서 확인했다.

운영에서는 읽기 전용 트랜잭션으로 실제 관리자·대상 글·읽음 원장을 읽어 운영 집계와 후보 코드를 대조했다. 이미 읽은 관리자는 0 유지, 미읽음 관리자는 0→1, 비권한 회원 0, 비로그인 401이었다. 계정 로그인 세션을 만들거나 원장·읽음 기록을 변경하지 않았다. 실제 회원 브라우저 세션 검증은 수행하지 않았고 UI 제품 코드·DB 스키마·수집·푸시가 변경되지 않아 전체 UI 빌드와 운영 쓰기 검사는 제외한다.

기존 서버 부분 배포에 서버가 직접 import하는 기존 `src/utils/*.mjs`를 허용해 변경 모듈 두 개를 함께 반영한다. 테스트 제외·운영 원본 해시·fuzz=0·구문 검사·백업·실패 복구는 그대로 유지한다. UI 기본 공개 집계는 바뀌지 않아 프런트 번들을 재배포하지 않는다. 롤백은 배포 백업의 두 모듈과 version.json 복원이며 데이터 마이그레이션이 없다.
