# 장르 공통 화면과 씬 안내의 소유 경계

날짜: 2026-09-10. 상태: 사용자 요구를 잘못 해석한 안내 화면 결정으로 철회. [기존 화면의 장르별 데이터 전환 결정](2026-09-11-shared-genre-data-selection.md)으로 대체. 아래 내용은 당시 판단과 배포 이력이다.

## 요청과 기존 구현 판정

스윙 사이트의 살사 버튼에서 조사한 장소·동호회·강습 링크를 보여주되, 여러 장르의 화면을 복제하지 않고 공통 틀을 한 번 수정하면 함께 반영한다. DB도 장르별로 분리하지 않는다.

- **기존 구현 있음:** `server/cafe24/schema.sql`의 이벤트 `dance_scope`·`activity_type`, `events-api.js`의 장르 조건, `useCalendarEventsQuery`·`useListViewEvents`의 장르별 조회/캐시, 공통 캘린더·리스트·지도·상세보기, `danceTaxonomy.ts`의 다섯 장르, `collection-registry.mjs`의 소스 및 연구 프로필.
- **일부 연결만 있음:** 캘린더 장르 버튼은 스윙 외에 준비 중 메시지를 표시하고 주소도 스윙으로 되돌렸다. `b79d9ba4f` 등 기존 genre guard는 검증되지 않은 확장 장르 이벤트를 공개 화면에 열지 않기 위한 경계였다.
- **없음:** 조사 결과를 방문자가 읽는 공통 안내 화면. 그래서 데이터와 렌더러를 나눈 공통 `DanceSceneGuide` 하나를 추가한다. 장르별 페이지·DB·큐·상태값을 새로 만들지 않는다.

## 결정

1. `/calendar?dance=<기존 장르>` 주소를 재사용한다. 스윙은 기존 이벤트 화면, 확장 장르는 공통 씬 안내로 연결한다. 스윙 안내도 `section=guide`로 같은 렌더러를 쓴다.
2. 장르 선택은 `CalendarDanceScopeSwitch` 하나, 페이지와 사이트 헤더의 화면 판정은 `getCalendarGenrePage` 하나가 소유한다. 안내에는 월 이동·등록 작업·스윙 일정 조회가 마운트되지 않는다.
3. `danceSceneGuides.ts`는 방문자용 편집 콘텐츠(소개, 지역, 고정 링크)만 소유한다. `Partial<Record<CalendarGenreScope, ...>>`에 내용을 넣으면 같은 섹션·카드·모바일 화면에 반영된다. 비어 있는 장르는 준비 안내를 표시한다. 브라우저나 DB에 별도 연구 레코드를 복제하지 않는다.
4. 수집 실행·저장 허용은 기존 수집 레지스트리가 계속 소유한다. 안내에 출처가 소개됐다는 이유로 수집·자동등록을 활성화하지 않는다. 기존 과거 계정과 새 조사 계정의 관계가 미검증이므로 이번에 레지스트리를 덮어쓰지 않는다. 수집 승격 시 기존 원본 ID를 확인해 연결해야 한다.
5. 이벤트 장르 `dance_scope`와 활동 `activity_type`/`category`는 서로 다른 축이다. 살사를 class/social 카테고리에 추가하거나 장르별 이벤트 테이블을 만들지 않는다. 기존 스윙의 NULL 장르 호환과 자동등록 검수 경계는 유지한다.
6. 장르 전환 때 이전 이벤트 ID·일회성 스크롤을 제거하고 기존 view/filter는 보존한다. 뒤로가기·직접 링크도 같은 주소 판정을 쓴다. 포스터, 소셜 뱃지, 월별 모든 이벤트 표시 규칙은 변경하지 않는다.

## 검증과 롤백

검증 범위는 레거시/직접 링크, 확장 장르 안내, 장르 전환과 되돌아오기, 지역 필터, 데스크탑/모바일, 기존 캘린더 표시 회귀다. 등록 API·수집 작업·DB 스키마는 변경하지 않으므로 새 운영 데이터 쓰기나 스케줄 실행은 하지 않는다. 롤백은 프런트엔드 변경을 되돌리면 되며 데이터 마이그레이션이 없다.
