# 방문자 통계 계산 주기와 조회 비용

- 날짜: 2026-09-23
- 상태: 채택. closed-analytics-reports 결정의 오늘 실시간 원장 조회 부분을 대체한다.

## 책임과 데이터

기존 analytics-reports 서비스와 관리자 전용 site_usage_stats가 일별 결과의 유일한 소유자다. 오늘은 같은 저장소의 analytics-report:v2:live 단일 키를 교체하며 finalized=false와 snapshot_time 날짜로 구분한다. 일별 날짜 키는 확정 결과만 저장하므로 이전 버전으로 롤백해도 오늘 중간값이 과거 확정값으로 오인되지 않는다. 날짜가 끝나고 KST 00:35가 지나면 확정값으로 교체하고 이후 자동으로 바꾸지 않는다. 레거시 finalized 없는 v2 과거 행은 이미 마감된 것으로 읽는다. report_version은 계산 결과가 동일하므로 2를 유지한다. 일반 조회는 원장을 읽거나 보고서를 쓰지 않는다.

기존 stats cron을 매분 실행한다. 스케줄러와 수동 생성은 기존 DB 잠금을 공유한다. 오늘 갱신이 실패하면 이전 값을 보존하고, 2분 이상 지연 시 마지막 저장값임을 알린다. 화면에는 1분 갱신 기준을 표시한다. 관리자가 즉시 갱신하면 오늘을 직접 갱신하되 확정된 과거는 보존한다. 과거만 선택한 명시 원본 재생성은 기존 기능을 유지한다.

coverage의 first/last 및 updated_at을 재사용해 매분 전체 보고서 읽기를 피한다. 하루 한 번은 모든 날을 검사해 누락/손상을 복구한다. 초기 비압축 v2 행도 같은 보고서/inputs를 압축해 저장하고 coverage.storage_encoding으로 전환 완료를 표시한다. 새 소유 테이블이나 작업 큐가 필요하지 않다. 원장 전체 스캔은 관리자 기기의 기간 밖 연결 보호를 위해 자동 작업에 남기며, 수집·조회 요청에서 불필요한 전체 세션/보고서 전송을 제거한다.

## 전달과 계산

요약은 기존 report_part 모드로 제공하고 상세 배열·사용하지 않는 일별 항목 목록을 제외한다. 회원/Guest 목록은 별도 기존 RPC 읽기로 25명씩 제공하며 전체 수를 함께 반환한다. 기간 고유 방문자는 동결된 일별 입력을 합쳐 중복 제거하고 현재 일별 저장 입력을 더한다. 기간 결과의 임시 캐시는 최대 3개·60초이며 서비스에만 존재한다. 실패/pending은 재사용하지 않고 명시 재생성 시 비운다. 영속 원본은 여전히 일별 저장값이다.

관리자 기기 그래프는 원래 고정점 결과와 같은 연결 성분을 한 번씩 순회한다. KST 시간대는 +09:00 UTC 필드로 분류하고 날짜 표시 formatter는 재사용한다. 운영 입력의 전체 JSON 동등성과 경계 테스트로 결과를 검증한다.

## 수집과 레거시

findSessionLog는 기존 키 단건 조회를 먼저 쓰고, 예전 UUID 키는 기존 JSON 필드 조회(구형 MySQL LIKE fallback 포함)로 찾는다. 실패하면 신규 값으로 덮어쓰지 않는다. 레거시 데이터 삭제·일괄 키 변경·수집 정책 변경은 하지 않는다.

## 배포와 롤백

817e006f 배포의 실제 generic-data-api.js와 stats-api.js 해시를 고정하고 그 위에 해당 파일의 통계 변경만 적용한다. 서버 묶음·cron·통계 UI만 함께 배포한다. 초기 저장 전환과 오늘 저장에 성공한 뒤 화면을 전환한다. 실패하면 API 두 파일·묶음·cron·화면을 복구한다. 이미 압축된 v2는 이전 배포에서도 읽을 수 있다. 오늘 live 행은 이전 버전의 일별 날짜 키와 충돌하지 않으며 이전 버전의 마감 작업은 원래대로 별도 일별 결과를 만든다.
