# 교차 출처 소셜의 확정 속성 기반 중복 판정

- 날짜: 2026-08-12
- 상태: 채택, 운영 배포 전

## 배경

자동수집의 결정론 ID는 `source_url + date`를 사용하므로 같은 소셜을 Instagram과 Naver 카페가 각각 공지하면 서로 다른 후보가 된다. 기존 서버 보정도 같은 URL·같은 출처 또는 높은 제목 유사도를 중심으로 동작했다. 2026-08-12 스윙타임 수요 소셜은 두 원문의 날짜·장소·활동·DJ와 사진이 같았지만 출처명이 들어간 제목 유사도가 `0.40`으로 기준 `0.88`에 못 미쳐 두 번 등록됐다.

## 결정

1. `source_url + date` 결정론 ID는 출처별 수집 이력 보존을 위해 유지한다.
2. 운영 일정 중복은 별도 서버 계층에서 판정한다. 소셜에 한해 정확한 개최일, 정규화 장소, 활동 유형 `social`, 비어 있지 않은 DJ 전체 명단이 모두 같으면 출처와 제목이 달라도 같은 일정으로 본다. 반복 일정은 시작일~종료일 사이의 모든 날이 아니라 `event_dates`의 실제 개최일만 비교한다.
3. DJ 명단은 구조화 필드와 저장 일정의 DJ 필드를 우선하고, 없을 때만 `DJ … | 제목` 또는 제목 끝의 DJ 표기를 사용한다. 명단은 정규화·중복 제거·정렬한 뒤 정확히 비교한다.
4. `미정`, `추후 공지`, `TBD`처럼 확정되지 않은 DJ는 중복 근거로 사용하지 않는다. 날짜·장소·활동·DJ 중 하나라도 다르면 이 규칙으로 자동 병합하지 않는다.
5. 같은 판정은 후보 저장 시점과 자동등록 직전에 모두 실행한다. 자동등록 직전 충돌은 HTTP 409로 종료하고 후보를 `duplicate`로 보존한다.
6. 중복 후보에는 유지할 운영 일정의 ID·제목·날짜·원본 URL·판정 사유를 저장한다. 제거된 일정으로 향하는 `registered_event_id`와 `registered_at`은 남기지 않는다.
7. `regular-social:*` 생성 일정은 DJ가 미정이므로 이 교차 출처 규칙의 확정 중복이 아니다. 검증된 실제 소셜이 생성 일정을 교체하는 기존 정책을 유지한다.
8. 현재 중복은 우선순위가 높은 스윙타임 공식 Instagram 일정을 유지하고 스윙프렌즈 Naver 카페 일정을 제거한다. 삭제 전 운영 행과 후보 원본을 별도 백업하고, 후보는 삭제하지 않고 중복 이력으로 보존한다.

## 운영 경계

- 이 규칙은 자동수집 후보에만 적용한다. 관리자가 의도적으로 등록하는 일정은 기존 권한과 검수 흐름을 유지한다.
- 사진 유사성은 이번 사건의 보강 근거지만 자동 판정의 필수 키로 사용하지 않는다. 이미지 처리 실패가 중복 방어를 무력화하지 않게 하기 위함이다.
- 서로 다른 DJ가 같은 장소에서 같은 날 진행하는 경우는 별도 일정일 수 있으므로 자동 중복으로 만들지 않는다.

## 검증

- 교차 출처·상이한 제목에서도 확정 속성 네 가지가 같으면 차단
- DJ 상이·미정, 날짜 상이, 활동 유형 상이 사례는 차단하지 않음
- 복수 DJ의 순서 차이와 `스윙타임`/`스윙타임바` 장소 표기 정규화
- 중복 후보 전환 시 과거 등록 ID·시각 제거
- 운영 미래 소셜 199행 읽기 전용 대조에서 신고된 1그룹만 검출
