# 기존 화면에서 장르별 데이터만 전환

날짜: 2026-09-11. 상태: 구현·로컬 검증, 배포 확인 대기.

## 원인과 기존 책임

사용자가 원한 것은 기존 메인·캘린더·원데이·장소 화면의 데이터 전환이었다. a1c6af62는 살사 선택을 별도 씬 안내로 바꿔 요구를 잘못 구현했다. 앞선 안내 화면 결정은 철회하며 안내 컴포넌트·스타일·주소 판정 파일을 제거한다.

기존 구현은 **일부 있음**이다. `danceTaxonomy`와 이벤트의 `dance_scope`, `events-api`의 scope 조건, 캘린더·리스트·지도 조회/캐시는 이미 있다. `b79d9ba4f`의 스윙 공개 가드는 미검증 타장르 공개를 막았고, `efaf276f0`의 메인 광고 최소 개수 보충은 부족한 장르의 카드 수를 채웠다. 이번 요구는 선택 장르 데이터만 같은 UI에 보여주는 것이므로 강제 스윙·타장르 보충을 제거하고 기존 scope 판정으로 연결한다. 광고의 미래 날짜·중복 제거·최대 개수, 수집 원문·검수 정책은 유지한다.

원데이 링크는 기존 `swing_oneday_recruit_links` 논리 테이블과 등록 모달, 장소는 `venues.category`와 VenueTabBar/등록 모달이 소유한다. 새 DB·테이블·장르 페이지·큐·상태를 만들지 않는다. 원데이 레코드에만 기존 장르 분류의 `dance_scope`를 선택 필드로 추가한다. 해당 레코드에는 기존 genre 정보가 없어 별도 목록 없이 장르를 구분할 최소 연결이 필요하다. 스키마는 기존 generic_records JSON이며 물리 마이그레이션은 없다.

## 결정

- URL `dance`를 메인·캘린더·일정·원데이 링크의 선택 기준으로 통일한다. 장르별 컴포넌트를 복제하지 않고 동일 렌더러를 쓴다. 기존 view/filter, 포스터, 소셜 뱃지, 월의 모든 이벤트 표시를 유지한다.
- 메인 신규 이벤트가 비어도 기존 배너 프레임·장르 버튼·바로가기를 유지한다. 다른 장르로 빈자리를 채우지 않는다.
- 원데이 레코드의 NULL/누락 scope는 스윙으로 해석한다. 기존 스윙 DB 행이 없으면 정적 스윙 링크 폴백을 유지한다. 살사 행이 생겨도 스윙 폴백이 사라지지 않는다.
- 연습실 화면에 기존 스윙바 옆 살사바 탭과 기존 등록 모달의 분류만 추가한다. URL category와 기존 category 조회로 같은 목록/지도를 재사용한다.
- 연구 문서는 별도 Git 문서에 둔다. [회원 글 대조](../salsa-member-evidence-2026-09-10.md)의 최근 원문 확인 링크 4건과 공식 장소 1건을 기존 저장 함수로 반영한다. 가입자 프로필·미검증 행사·가격·좌표를 추정 저장하지 않는다. 원데이 지도 좌표는 기존 서울 지역 중심 표시를 사용한다.
- 운영 반영 전 기존 ID/URL/이름 중복을 읽고 일치하지 않는 기존 행은 덮어쓰지 않는다. 적용 대상과 원장을 제한 접근 백업하고 새 5개 ID만 추가한다. 롤백은 해당 ID만 기존 삭제 함수로 제거한 뒤 프런트엔드를 되돌린다.
- 자동수집 확대와 링크 공개는 별도다. `expanded-research`/`expanded-ingestion`, 고정 소스 레지스트리와 후보 검증 API를 재사용한다. 이번 작업은 살사 자동수집 가동 완료가 아니다.

## 검증

기존 날짜·장르 분류·메인 우선순위·하단 이동·장소 바로가기·캘린더 전체 표시 회귀와 원데이 레거시/살사/빈 장르 경계를 선택했다. 실제 운영 DB를 연결한 데스크탑 1440px·모바일 390px에서 메인/원데이/장소/캘린더 전환·뒤로가기·포스터·뱃지 15개 검사가 통과했고 브라우저 런타임 오류는 없다. 운영 살사 이벤트가 비어 있어 브라우저 내부 샘플 응답으로 데이터가 있는 살사 메인/캘린더·다른 장르 배제·비드래그 이미지 8개도 확인했다. 샘플은 운영에 저장하지 않았다.

관련 Vitest 8개 파일 47건, 대상 ESLint 오류 0건, Cafe24 로컬 빌드와 diff 공백 검사도 통과했다.

수집 실행·후보 승인·알림 전송 코드는 변경하지 않아 새로운 운영 수집이나 알림 테스트를 실행하지 않는다. 기존 저장 구조와 캘린더 렌더러의 소유자는 유지되어 중복 구현이 없다.
