# Jev 개발·운영·수집 적용 분석

기준일: 2026-09-21. 상태: 조사 및 제안. 도입 결정, 설치, 유료 호출, 운영 변경 없음.

## 판단

이 프로젝트에는 작은 의미 판단을 반복하는 용도로 평가할 가치가 있다. 첫 후보는 개발 변경의 정책 적합성 검토와 수집 후보의 활동·혜택 문맥 분류다. 전체 수집기나 포스터 판독기를 바로 교체하는 것은 현재 입출력 계약과 맞지 않는다. 아래 효과는 실측 성능이 아닌 코드와 자료에 근거한 적용 가설이다.

조사는 현재 작업 트리, 관련 테스트·이력·결정 문서와 로컬 실행 요약을 대상으로 했다. 배포본 일치나 운영 DB는 이번 조사에서 확인하지 않았다. 기존 미커밋 변경이 다수 있어 분석 문서 외 실행 코드는 수정하지 않았다.

## 확인한 기능과 게임 영상의 의미

- [공식 모델 문서](https://docs.typesafe.ai/models): Jev 1.13.0은 텍스트/JSON 입력과 선택·점수형 판단을 제공하며 이미지 직접 입력은 지원하지 않는다. 입력 100만 토큰 $0.042, 출력 무료. 한국어를 포함한 비영어 성능은 자체 표본으로 확인해야 한다.
- [공식 한계 문서](https://docs.typesafe.ai/model-jaggedness/jev-1.13): 날짜 대소 비교·계산은 코드가 맡고, 추출은 가능한 값을 먼저 모아 선택시키는 구성이 적합하다. 임의 문장 생성과 무관한 장문 입력은 적합하지 않다.
- [사용자 제공 영상](https://www.youtube.com/watch?v=Evq6yIh4f1I&t=1412s)의 23:32–24:43 스크립트는 화면 캡처 → OCR 등으로 좌표 추출 → 텍스트 상태를 Jev에 전달 → 코드가 행동 실행하는 구성을 설명한다. 제작자의 실제 비공개 코드, OCR 엔진, 정확도는 확인하지 않았다.
- 따라서 게임처럼 포스터 판독과 Jev 판단을 결합할 수 있다. 다만 앞 단계가 날짜나 DJ를 잘못 읽으면 Jev도 잘못된 텍스트를 기준으로 판단한다. 원본을 다시 보는 독립 검증은 별도 역할이다.

## 사이트 개발에 적용할 지점

| 우선순위 | 적용 | 입력과 판단 | 기존 구현과 연결·제한 |
| --- | --- | --- | --- |
| 높음 | 변경 코드의 프로젝트 정책 검토 | 관련 diff·직접 호출부·규칙을 주고 시간 전용 UI 추가, 달력 항목 생략, 자동등록 검수 우회 가능성을 질문 | ESLint·타입·Vitest·Playwright는 이미 있음. Jev는 의미 판단 보조로 추가할 부분만 있음. 실제 동작 검증과 병합/배포 승인 대체 불가 |
| 높음 | 관련 구현·문서 후보 정렬 | rg로 찾은 제한된 후보 중 같은 책임·관련 불변조건을 가진 함수/문서 선택 | 검색은 이미 있음. 기존 구현 재사용 조사 지원. 후보 밖 파일이나 과거 도입 의도까지 찾아냈다고 간주하지 않음 |
| 중간 | 완료 보고의 근거 대조 | “테스트 통과”, “중복 등록 보호 유지” 같은 주장과 실제 출력/수정 내용을 비교 | 실행한 테스트 범위 안에서만 판단. Jev가 테스트를 실행하거나 정확성을 증명하지 않음 |
| 중간 | UI 시나리오 점검 | DOM/접근성 텍스트와 요구사항으로 버튼 역할·누락 문구·등록 동선 모순 판단 | DOM 추출 및 브라우저 테스트와 결합. 잘림·겹침·색상·이미지 상태는 좌표 검사나 시각 모델 필요 |
| 낮음 | 테스트·운영 문제의 분류 | 실패 출력과 알려진 원인 후보의 관련성 판단 | 테스트를 생략하는 근거로 쓰지 않음. 기존 문제 알림 분류·반복 억제와 중복 구축하지 않음 |

권장 개발 흐름은 수정 단위가 끝났을 때 관련 diff와 제한된 근거로 한 번 보조 검토하고, 지적된 지점을 실제 코드/테스트로 확인하는 방식이다. 매 편집마다 전체 저장소를 보내고 점수가 낮으면 무한 재수정하는 방식은 비용과 오탐을 늘릴 수 있다. 단순 패턴으로 확정 가능한 규칙은 정적 검사에 남긴다.

검토 질문 예시는 “변경 후 별도 시간 입력 UI가 생기는가”, “달력에서 같은 날 행사 일부가 숨겨지는가”, “이미 있는 검증 함수를 우회하는 저장 경로가 생기는가”다. 답은 적합/검토 필요/근거 부족 등 유한 선택으로 받고, 설명 문장은 주 모델 또는 사람이 근거와 함께 작성한다. Jev 점수만으로 자동 수정하지 않는다.

공개 구현도 확인했다.

- [jev-mcp](https://github.com/jkudish/jev-mcp)는 근거 대조, 후보 검색·재정렬, 분류, 정규식 후보 기반 추출, diff 검토 도구를 제공한다. 초기 커뮤니티 소프트웨어이며 소개의 지연 시간은 이 프로젝트 실측이 아니다.
- [jev-semantic-reviewer](https://github.com/sglenon/jev-semantic-reviewer)는 Python/TypeScript/TSX의 변경 함수 정적 분석과 선택적 의미 검토를 구현한다. 중복 후보 탐색과 기존 관례 검색은 문서상 예정 항목이다. 핵심 수집·서버 파일이 .mjs/.js인 이 프로젝트 전체를 그대로 지원한다고 볼 수 없다. 의미 판정으로 리뷰를 실패 처리하지 않는 설계다.

이번에는 해당 패키지나 스킬을 설치하거나 PR 댓글을 게시하지 않았다.

원문/첨부 포스터 → 날짜별 활동·장소·DJ 추출 → 정확 인용과 원본 연결 검증 → 기존 자동등록 API → 이벤트 변경 잠금 안 충돌 재검사 → scraped_events 원장/events 공개 결과.

특히 `review`를 실패로 해석하면 안 된다. `extractSocialScheduleWithAi`는 검증 승인 외 결과를 review로 반환한다. 호출부는 통계를 먼저 올린 뒤, `decision=none`, confidence≥0.98, events=[]이면 정상적인 “수집 대상 없음”으로 처리하고 blocker로 남기지 않는다. 따라서 443건을 실패나 절감 가능한 비싼 호출로 계산할 수 없다.

실제 extraction blocker는 113회이며 `(sourceId, sourceUrl)` 조합은 17개다. 이유 문자열에는 날짜 힌트 누락이 65회, 날짜 인용 불일치 8회, 장소 인용 불일치 6회 등장한다. 이유는 중복될 수 있다. 이는 일부 출처에서 반복 보류가 집중됨을 보여주지만 동일 URL의 원문·포스터가 계속 같았다는 증거는 아니다.

다른 단계 blocker도 discovery 387회, registration-policy 106회, verification 39회, registration-reconciliation 200회 있었다. 단계 간 중복과 재발 기록이므로 합계로 전체 실패율을 계산하지 않는다. 로그인/원문 접근 실패와 실제 DB 충돌은 Jev 분류 성능으로 해결되지 않는다.

## 수집에서 우선 평가할 판단

1. **각 날짜의 역할 구분.** 강습 모집 본문의 나중 졸업 파티 언급 때문에 강습일이 소셜로 분류되는 경계를 판단한다. 저장소의 2026-08-28 결정 문서에 실제로 기록된 문제다. 전체 글을 한 번 분류하지 않고, 날짜와 연결 문장별로 강습/소셜/졸공/휴무/불명확 중 선택한다. 기존 주 행사 중심 규칙을 재사용하며 대체를 전제하지 않는다.
2. **실제 혜택과 일반 요금 구분.** 정상적인 선납·파트너·재수강 요금 조건과 별도 캠페인/무료 체험을 구분한다. 선택형 작업과 잘 맞으며 기존 텍스트 검토 입력을 이용할 수 있다. 한글 약어·문맥 정확도는 미검증이다.
3. **근거 문장 선택.** 원문 문장이나 OCR 블록에 번호를 붙이고 날짜·장소·DJ를 뒷받침하는 블록을 고르게 한다. 인용문은 선택된 원문에서 코드가 복사하여 생성 오차를 줄인다. 문장을 선택했다고 의미가 맞는 것은 아니므로 기존 검증을 유지한다.
4. **애매한 후보의 검토 순서.** 누락 가능성이 크거나 당일 대상인 기존 pending 후보를 먼저 보여줄 수 있다. 필수 수집원이나 당일 보충 대상을 Jev가 제거하지 않는다.

여러 독립 질문은 같은 원문으로 묶어 평가할 수 있다. 활동 종류, 날짜의 역할, 혜택 문맥, 근거 존재 여부는 별도 질문으로 분리하고 결과 조합은 코드가 맡는다. [공식 fan-out 문서](https://docs.typesafe.ai/patterns/fan-out). 질문을 더하면 입력 비용도 늘 수 있다.

포스터에만 내용이 있고 캡션에는 “이번 주 공지”만 있는 게시물은 이미지 판독 전에 텍스트 분류로 버리면 누락될 수 있다. 초기에는 Jev 결과로 원문/이미지를 생략하지 않고 기존 결과와 비교해야 한다.

## 이미지 처리와 반복 비용

조사한 수집 경로에서는 Codex의 이미지 입력과 의미 추출이 결합되어 있다. 해당 경로에서 별도 OCR 엔진을 연결한 구현은 확인하지 못했다. 따라서 “OCR + Jev”는 OCR을 추가하고 한국어 포스터 성능을 비교해야 하는 별도 작업이다.

후보 구성은 텍스트 원문 → 기존 파서 → Jev 의미 판단, 이미지 원문 → 기존 시각 판독 또는 평가를 통과한 OCR → Jev 의미 판단이다. 다중 포스터의 원본 번호·블록 위치·날짜/DJ 연결을 유지해야 한다. 이미지 인덱스와 원본 근거가 사라지는 단순 평문 병합은 불충분하다.

반복 판독 절감도 별도 가설로 평가할 가치가 있다. 현재 처리한 URL 체크포인트와 동일 콘텐츠의 AI 결과 캐시는 다른 책임이다. URL이 같아도 포스터가 바뀔 수 있으므로 재사용 여부에는 원문/이미지 내용, 모델·추출 규칙 버전, 기준일 등 판단 입력의 동일성이 필요하다. 순수 추출 결과를 재사용하더라도 현재 날짜 적격성, 관리자 삭제, DB 충돌, 최종 등록 권한은 다시 검사해야 한다. 반복 URL만으로 캐시 적중률이나 절감률을 제시하지 않는다.

## 비용 판단

공식 단가를 이용한 가정 계산이며 실제 요청량 예측이 아니다. 요청의 원문과 질문을 합친 과금 입력 토큰을 기준으로 한다.

| 시나리오 | 건수 × 입력 토큰 | Jev 비용 |
| --- | ---: | ---: |
| 수집 판단 1천 회 | 1,000 × 3,000 | $0.126 |
| 수집 판단 1만 회 | 10,000 × 3,000 | $1.26 |
| 수집 판단 10만 회 | 100,000 × 3,000 | $12.60 |
| 개발 보조 검토 1천 회 | 1,000 × 12,000 | $0.504 |

OCR, 시각 모델, 기존 LLM 재검토, 실패 재시도, 네트워크/중개 비용은 별도다. 현재 Codex CLI 호출의 요약에는 토큰 usage가 없고 실제 구독/API 청구 방식도 검증하지 않아 기존 금액 대비 절감률을 확정할 수 없다.

기존 의미 판단 한 건 비용을 C_old, Jev 한 건 비용을 C_J, Jev 후 기존 모델로 넘어가는 비율을 f라 하면 해당 단계의 새 비용은 `N × (C_J + f × C_old)`다. 줄일 수 없는 원문 수집·이미지 판독·필수 검증 비용은 여기에 별도로 더한다. 기존 호출을 실제로 제거할 때만 이 단계에서 `C_J < (1-f) × C_old`인 만큼 절감된다. 검토용으로 양쪽을 모두 호출하는 평가 단계는 추가 비용이다.

## 평가와 적용 순서

1. 기존 테스트와 원문 확인 가능한 운영 사례에서 한국어 평가 표본을 만든다. 정상 소셜, 강습 중 파티 언급, 휴무, 과거 글, 여러 날짜, 실제 혜택, 일반 가격 조건, 이미지 전용 공지를 포함한다. 초기 규모 200–400개는 제안일 뿐 아직 수집·라벨링하지 않았다.
2. 같은 출처/게시물/행사의 반복 기록이 학습용 임계값 조정 표본과 최종 평가 표본 양쪽에 섞이지 않게 분리한다. 기존 AI 결과를 정답으로 그대로 사용하지 않고 사람이 원본을 확인한다.
3. 실제 등록 없이 기존 판단과 Jev를 비교한다. 날짜별 누락, 잘못된 승인, 근거 없는 선택, 불확실 비율, 지연, 과금 입력, 기존 모델로 넘어간 비율을 측정한다. 현재 dry-run은 AI 호출 뒤에 적용되어 무료 실행을 뜻하지 않는다. 기존 exception backtest는 AI 추출을 끄므로 Jev 평가를 대신하지 못한다.
4. 한국어 정확도가 확인되면 개발 보조 검토와 관리자 우선순위부터 사용하고, 혜택 등 좁은 텍스트 판단의 대체를 검토한다. 자동 공개 권한 확대는 이 평가의 전제가 아니다.
5. API 오류·불명확 판정은 기존 경로로 복귀한다. 버전은 고정하고 결과 변화는 재평가한다. [공식 confidence 문서](https://docs.typesafe.ai/confidence)의 수치는 현재 LLM이 자기보고하는 0.98과 같은 정확도 척도가 아니므로 그대로 ai_verified=true에 연결하지 않는다.

회귀 경계는 영향을 받는 텍스트/이미지, 단일/복수 날짜, 자동/수동, 승인/거절/보류, 정상/실패/재시도다. 같은 장소·날짜 충돌 보류, 엄격 중복, 정규 생성본 교체, 관리자 삭제 보호, 잠금 안 재검증은 유지한다. 시간 전용 필드·알림 시간 노출은 추가하지 않는다.

이번 변경은 조사 문서뿐이라 실행 테스트·수집 재실행·배포는 제외했다. 새 함수·DB 필드·테이블·큐·상태값·판단 소유자는 추가하지 않았다.
