# 살사 수집 확대와 실제 운영 확인 — 2026-09-22

> 후속 갱신: 사용자의 등록 지시 후 강습 50·소셜 10·행사 1, 총 61건 공개 등록을 완료했다. 아래는 최초 연결 실행 시점의 기록이다. 최종 수치·원문 검수·추가 수정은 [후속 보고](salsa-social-followup-2026-09-22.md)를 따른다.

## 최초 실행의 결론과 실제 결과

살사 정체의 주원인은 출처 목록과 실제 실행기의 연결 누락이었다. 9월 11일 보니따·DSN을 한 차례 저장·공개 등록했지만 신규 게시물 탐색기는 미연결 상태였고, 예약 실행은 스윙에 한정됐다. 이번에는 기존 공통 수집기에 공개 일정 읽기를 연결하고 살사 예약 실행을 활성화했다.

- 운영 후보 신규 저장 **48건**: JDC 강습 45건, 보니따 9/22 소셜 1건, DSN 11/19·11/26 소셜 2건. 읽기 전용 서버 원장 재조회에서도 48건 모두 미수집·미승인·공개 이벤트 연결 없음으로 확인했다.
- **공개 신규 등록 0건**. JDC는 새 출처의 수동 검수 정책을 유지한다. 소셜 3건은 기존 AI 검증이 소셜 유형/DJ 근거를 승인하지 않아 검수 대기로 남았다. 승인값을 덮어쓰거나 검증을 끄고 재등록하지 않았다.
- 기존 DSN 8건은 저장 API가 중복으로 제외했다. 사전 공개 API 조회에서 오늘 이후 살사 일정은 이 8건뿐이었다.
- 새 출처 16개(Instagram 15개, JDC Meetup 1개)를 기존 레지스트리에 추가하고 턴·보니따의 현행 계정 URL을 연결했다. 사이트가 접근 가능하다는 사실, 원문 경로 발견, 미래 일정 확보, 후보 저장, 공개 등록은 서로 다른 결과다.
- 공개 원문·카페 7개 출처는 매일 12:10/18:10, Instagram 17개 출처는 매일 14:10에 기존 Mac 실행기로 확인한다. 스윙 실행 목록은 그대로 분리된다. launchd 두 작업 등록 및 대기 상태를 확인했으며 첫 예약 실행은 아직 도래하지 않았다.

## 실제 씬 관찰과 수집 전략

이번 조사에서 살사는 단순한 ‘서울 살사’ 검색보다 **장소 운영자·동호회·강사/학원·행사 주최자**를 나누어 추적해야 한다는 점이 확인됐다. 전국 활동 인구나 시장 점유율을 산출한 조사는 아니다.

1. **바 중심의 주간 소셜**: [보니따 공식 채널](https://pf.kakao.com/_RIMtM/114598795)은 날짜마다 DJ, 메인홀/다른 홀, 음악 비율, 휴무가 다르다. 화요일 메인홀 DJ 길거리와 키좀바홀 DJ 뮤짱을 하나의 살사 DJ 명단으로 합치면 안 된다. 주간 글은 일자별로 분리하고 게시 시점을 기준으로 연도를 확인한다.
2. **강습과 소셜의 결합**: [DSN](https://www.meetup.com/dsn-crew/events/)은 수요일 강남턴과 목요일 클럽 라틴의 위치가 다르고 부속 강습은 별도 스튜디오를 사용한다. 카드의 실제 회차 날짜와 소셜 문단을 읽으며 오래된 최초 시작일·접수 마감일을 다음 행사 날짜로 쓰지 않는다.
3. **개별 회차 강습과 복수 지역 운영**: [JDC](https://www.meetup.com/seoul-latin-dance-salsa-bachata-jhonatan-jimenez/events/)는 실제 예정 카드에 서울 강남과 인천 송도의 수업을 게시한다. 본문에 여러 요일 시간표가 함께 있어 카드 날짜의 요일 문단만 남긴다. 날짜를 반복 규칙으로 생성하지 않으며 강습 후 소셜을 별도 행사로 만들지 않는다.
4. **지역 동호회/학원의 공지 분산**: 부산·대구·대전·광주 표본에서 Instagram 소개와 카페/Band 연결, 강습·정모·영상·후기가 섞여 있었다. [전국 디렉터리](https://latindance.kr/clubs-en)의 렌더링된 93개 카드는 원문 경로 지도이지 활동 단체 93곳 또는 확보 일정 93건이라는 뜻이 아니다. 이번 Instagram 4개 소스 시험에서는 미래 살사 후보가 추가되지 않았고 바야는 로그인 제한으로 중단했다.
5. **페스티벌은 별도 원문 확인 축**: [SIDF 공식 페이지](https://sidf.kr/)는 2027-04-23~25를 공지한다. [부산 페스티벌 발견 페이지](https://www.salsavida.com/event/south-korea/busan/busan-salsa-bachata-festival/)와 다른 허브 사이에는 일자·회차 표기 차이가 있어 원 주최자 확인 전 저장하지 않았다. 검색어에는 BSBF, SIDF, 제주 행사도 추가했지만 발견용 검색어가 곧 실행 완료/공개 일정은 아니다.

## 구현 판정·불변조건

**일부 있음.** `collection-registry`, `candidate-utils`, `swing-daily-native`, `ingestion-progress`, 기존 후보 저장/등록 API, launchd 실행기와 단일 실행 잠금을 재사용했다. 새 DB/큐/상태값/등록 API는 없다. `public-schedule-sources.mjs`는 기존에 없던 카카오·Meetup 공개 DOM 해석만 소유하며 후보 정규화·ID·등록 판단은 기존 소유자에게 넘긴다.

증상 → 출처 선택/공개 문서 해석 → 후보 저장·등록 → 후보 원장/공개 API 경로를 조사했다. 과거 `expanded-genre-native`의 지원 목록은 dancecode/koreatango 두 개뿐이고 현행 공통 수집기에는 카카오/Meetup 분기가 없었다. 이전 보고서도 이 미연결을 명시했다. 이 확인 뒤 확장 전용의 또 다른 저장기를 만들지 않고 공통 실행기에 연결했다.

보호 목적은 원문·날짜·활동·장소·DJ의 근거 없는 자동 등록, 허브 복제, 재시도 중복, 다른 장르 혼입을 막는 것이다. `ab6fdb53b`의 제한된 확장 수집, `fe2b77c6`의 근거 있는 소셜, `3b7dbc492`/`d8ab0f9e8`의 결정적 URL 정규화, `8a73c84ee`의 체크포인트 목적과 직접 호출부·기존 테스트를 확인했다. 이번 연결은 그 보호를 낮추지 않는다.

- 미래 날짜만, 강습은 실제 게시된 회차만, 소셜은 일자/홀/DJ 근거를 유지한다.
- 취소·휴무·오래된 연도·요일 충돌·연락 담당자 DJ·다른 홀의 DJ를 제외한다.
- Meetup 언어 경로와 추적 쿼리는 기존 URL 정규화에서 제거한다. 숫자 ID/별칭 ID는 임의 변환하지 않고 기존 내용/운영 중복 검사로 처리한다.
- 이미지 없는 강습과 기존 등록 소스의 명시 DJ 소셜 정책을 재사용한다. 날짜와 대응이 확인되지 않은 주간 갤러리 이미지를 특정 날짜의 포스터로 임의 배정하지 않는다.
- 별도 시간 필드는 만들지 않는다. 원문의 자유 형식 설명은 유지한다.
- 살사 이어읽기는 기존 상태 구조를 사용하고 파일명만 프로필/장르별로 분리한다. 스윙 체크포인트·같은 날 복구 실행 조건은 보존한다.

## 검증과 남은 경계

운영 원장 48건 모두 `is_collected=false`, `auto_registration.ready=false`, 공개 이벤트 ID 없음. 공개 API의 작업 전후 살사 8건은 ID뿐 아니라 전체 레코드가 동일하다. 저장 성공과 공개 등록 성공을 별도로 확인했으며, 기존 공개 일정 변경이나 이번 후보의 공개 노출은 없다.

수집 표준 전체 통과. 기존 테스트에 공개 회차·휴무·연도/요일·홀 분리·부속 강습·연락 DJ·바차타 전용 강습·언어 URL 중복·스윙/살사 상태 분리를 추가했다. 등록 연결 48개, 동일 장소 충돌 8개, AI 원문 검증 38개 테스트도 통과했다. 공개 DOM에서 카카오/Meetup을 실제 읽었고 지방 4개 Instagram 및 기존 강습 게시판 4곳도 저장 없이 시험했다. 새 실행 설정은 문법 검사와 launchd 등록 상태를 확인했다.

페이지 확장 결과는 로딩에 따라 달랐다. DSN 첫 시험 18개 후보와 실제 저장 실행 11개 후보를 혼동하지 않는다. 공개 소셜 실제 실행은 보니따 1·DSN 10개 후보를 처리해 신규 3·기존 중복 8로 끝났다. Meetup 전체 표시 숫자는 전체 미래 일정 확보 수가 아니다. JDC 실제 실행은 카드 60개에서 요일/살사 근거가 있는 후보 45개를 저장했다.

새 화면·알림·DB 스키마·서버 배포 변경이 없어 프런트 빌드/전체 UI 테스트/강제 배포는 제외했다. 자동 검증 거절은 재시도로 승인될 때까지 반복하지 않았다. 승인 전 공개 등록이 없으므로 알림 생성도 없다. 이번 신규 예약 작업의 Telegram 전송은 비활성으로 두었다.

실행 증적은 `/tmp/salsa-*-20260922.*`에 보관한다. 인증 정보와 원문 채널 접근 코드는 문서·테스트에 기록하지 않았다. 롤백은 새 launchd 두 작업을 해제하고 이번 수집기 변경만 되돌린다. 운영 후보는 원장에 남겨 수동 검수하며, 다른 후보/공개 이벤트를 일괄 삭제하지 않는다.
